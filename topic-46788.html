Rutas de Documentos, Escritorio y Descargas con SHGetKnownFolderPath

Hola a todos:

Seguimos con la serie de ejemplos de programación Windows con FiveWin. En el foro ya hay ejemplos clásicos para obtener carpetas especiales con SHGetFolderPath y los CSIDL numéricos; hoy vemos la API que los sustituye desde Windows Vista: SHGetKnownFolderPath, que identifica cada carpeta por un GUID (su KNOWNFOLDERID) en lugar de por un número. Además, resuelve una carpeta que las clásicas no cubren: Descargas no tiene CSIDL equivalente, solo existe como Known Folder.

Lo que dice la documentación de Microsoft

  • SHGetKnownFolderPath recibe la carpeta como REFKNOWNFOLDERID (un GUID), unos flags (0 vale para el caso normal), un hToken (NULL pide la carpeta del usuario actual, que es el uso habitual) y devuelve la ruta en un PWSTR.
  • La cadena devuelta es Unicode (UTF-16), no lleva barra final ("C:\Users" y no "C:\Users\") y hay que liberarla con CoTaskMemFree, tanto si la llamada tiene éxito como si no.
  • Las tres carpetas del ejemplo son de tipo PERUSER: dependen del usuario y del equipo; no conviene guardarlas como si fueran constantes.
  • Los GUID de Documentos, Escritorio y Descargas son {FDD39AD0-238F-46AF-ADB4-6C85480369C7}, {B4BFCC3A-DB2C-424C-B029-7FE99A87C641} y {374DE290-123F-4565-9164-39C4925E467B} (página KNOWNFOLDERID de la documentación).
  • Requiere Windows Vista o superior; al compilar, el SDK debe definir _WIN32_WINNT >= 0x0600. SHGetKnownFolderPath vive en shell32 y CoTaskMemFree en ole32: hay que enlazar ambas bibliotecas.

El ejemplo completo

Una ventana con un botón Consultar que rellena las tres rutas del usuario actual llamando a la API con cada GUID. El código C embebido va en el propio PRG. Dos detalles: el programa es ANSI y convierte el resultado UTF-16 a la codepage del sistema (CP_ACP); una ruta con caracteres no representables en esa codepage se vería mal en pantalla, y es una limitación del programa, no de la API. Y la conversión se comprueba: si falla, o si falla la propia API, el campo muestra el HRESULT en lugar de quedarse en blanco, y el buffer se libera en todos los caminos.

//----------------------------------------------------------------------------//
// KNOWNFOLDERS.PRG (v1)
// Carpetas especiales con SHGetKnownFolderPath (Known Folders):
// Documentos, Escritorio y Descargas
// Ejemplo didactico FiveWin (FWH) + Harbour
//
// Que muestra:
//   - SHGetKnownFolderPath recibe la carpeta por su KNOWNFOLDERID
//     (un GUID: FOLDERID_Documents, FOLDERID_Desktop,
//     FOLDERID_Downloads), no por el CSIDL numerico de las APIs
//     clasicas SHGetFolderPath/SHGetSpecialFolderPath (doc. Microsoft)
//   - Descargas solo tiene Known Folder: no existe CSIDL equivalente
//     en las APIs clasicas (doc. Microsoft)
//   - La cadena devuelta es UTF-16, no lleva barra final y hay que
//     liberarla con CoTaskMemFree, sean cuales sean el exito o el
//     fallo de la llamada (doc. Microsoft)
//
// Este programa es ANSI: convierte el resultado UTF-16 a la codepage
// del sistema (CP_ACP). Un caracter de la ruta que no quepa en esa
// codepage se vera mal en pantalla; es una limitacion del programa,
// no de la API.
//
// Las rutas dependen del usuario y del equipo (son carpetas por
// usuario, tipo PERUSER); lo que se ve en pantalla es lo que devuelve
// este equipo para el usuario actual (doc. Microsoft).
//
// Requiere Windows Vista o superior; al compilar, el SDK debe definir
// _WIN32_WINNT >= 0x0600 (doc. Microsoft). SHGetKnownFolderPath vive
// en shell32 y CoTaskMemFree en ole32: hay que enlazar ambas.
//
// Documentacion de Microsoft:
//   https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetknownfolderpath
//   https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid
//----------------------------------------------------------------------------//

#include "FiveWin.ch"

static oSayDocs, oSayEscr, oSayDesc
static oSayEstado

//----------------------------------------------------------------------------//

function Main()

   local oWnd

   DEFINE WINDOW oWnd ;
      FROM 0, 0 TO 330, 520 PIXEL ;
      TITLE "Carpetas especiales (SHGetKnownFolderPath)"

   @ 15, 15 SAY "SHGetKnownFolderPath da la ruta de una carpeta especial por su" OF oWnd SIZE 490, 15 PIXEL

   @ 33, 15 SAY "KNOWNFOLDERID (GUID). Descargas no tiene CSIDL clasico." OF oWnd SIZE 490, 15 PIXEL

   @ 70, 210 BUTTON "Consultar" OF oWnd ;
      SIZE 100, 26 PIXEL ACTION BtnConsultar()

   @ 112, 15 SAY "Carpetas del usuario actual:" OF oWnd SIZE 490, 15 PIXEL

   @ 136, 15 SAY "Documentos:" OF oWnd SIZE 140, 18 PIXEL
   @ 136, 160 SAY oSayDocs PROMPT "" OF oWnd SIZE 345, 18 PIXEL

   @ 158, 15 SAY "Escritorio:" OF oWnd SIZE 140, 18 PIXEL
   @ 158, 160 SAY oSayEscr PROMPT "" OF oWnd SIZE 345, 18 PIXEL

   @ 180, 15 SAY "Descargas:" OF oWnd SIZE 140, 18 PIXEL
   @ 180, 160 SAY oSayDesc PROMPT "" OF oWnd SIZE 345, 18 PIXEL

   @ 216, 15 SAY oSayEstado PROMPT "" OF oWnd SIZE 490, 18 PIXEL

   @ 246, 210 BUTTON "Cerrar" OF oWnd ;
      SIZE 100, 26 PIXEL ACTION oWnd:End()

   ACTIVATE WINDOW oWnd CENTERED

return nil

//----------------------------------------------------------------------------//

static function BtnConsultar()

   PonerValor( oSayDocs, KF_Path( 0 ) )
   PonerValor( oSayEscr, KF_Path( 1 ) )
   PonerValor( oSayDesc, KF_Path( 2 ) )

   oSayEstado:SetText( "Consultado para el usuario actual de este equipo" )

return nil

//----------------------------------------------------------------------------//

static function PonerValor( oSay, cValor )

   if cValor == NIL
      oSay:SetText( "(HRESULT " + ;
                    AllTrim( Str( KF_LastHResult() ) ) + ")" )
   else
      oSay:SetText( cValor )
   endif

return nil

//----------------------------------------------------------------------------//

#pragma BEGINDUMP

#include <windows.h>
#include <objbase.h>
#include <shlobj.h>
#include "hbapi.h"

// KNOWNFOLDERID de las tres carpetas (doc. Microsoft)
static const GUID s_FolderDocs = { 0xFDD39AD0, 0x238F, 0x46AF,
   { 0xAD, 0xB4, 0x6C, 0x85, 0x48, 0x03, 0x69, 0xC7 } };
static const GUID s_FolderEscr = { 0xB4BFCC3A, 0xDB2C, 0x424C,
   { 0xB0, 0x29, 0x7F, 0xE9, 0x9A, 0x87, 0xC6, 0x41 } };
static const GUID s_FolderDesc = { 0x374DE290, 0x123F, 0x4565,
   { 0x91, 0x64, 0x39, 0xC4, 0x92, 0x5E, 0x46, 0x7B } };

// Ultimo HRESULT de SHGetKnownFolderPath o del fallo de conversion
static HRESULT s_hrLast = S_OK;

// UTF-16 -> Harbour (ANSI, codepage del sistema). Devuelve 1 si
// convierte, 0 si falla; en caso de fallo deja el buffer terminado
// en nulo.
static int ToAnsi( const WCHAR *wBuf, char *szBuf, int cb )
{
   int nRes = WideCharToMultiByte( CP_ACP, 0, wBuf, -1, szBuf, cb,
                                   NULL, NULL );

   if( nRes == 0 )
   {
      szBuf[ 0 ] = '\0';
      return 0;
   }

   return 1;
}

// KF_Path( nCarpeta ) -> cRuta o NIL
// nCarpeta: 0 = Documentos, 1 = Escritorio, 2 = Descargas.
// La ruta devuelta no lleva barra final y se libera con
// CoTaskMemFree (doc. Microsoft).
HB_FUNC( KF_PATH )
{
   const GUID *pGuid;
   PWSTR pwszPath = NULL;
   char szBuf[ 512 ];
   HRESULT hr;

   switch( hb_parni( 1 ) )
   {
      case 0: pGuid = &s_FolderDocs; break;
      case 1: pGuid = &s_FolderEscr; break;
      case 2: pGuid = &s_FolderDesc; break;
      default:
         s_hrLast = E_INVALIDARG;
         hb_ret();
         return;
   }

   hr = SHGetKnownFolderPath( pGuid, 0, NULL, &pwszPath );

   if( SUCCEEDED( hr ) )
   {
      if( ToAnsi( pwszPath, szBuf, sizeof( szBuf ) ) )
      {
         hb_retc( szBuf );
         s_hrLast = S_OK;
      }
      else
      {
         s_hrLast = HRESULT_FROM_WIN32( GetLastError() );
         hb_ret();   // NIL
      }
   }
   else
   {
      s_hrLast = hr;
      hb_ret();   // NIL
   }

   // Liberar tanto si la llamada tuvo exito como si no
   // (doc. Microsoft); pwszPath vale NULL si no se asigno.
   if( pwszPath != NULL )
      CoTaskMemFree( pwszPath );
}

// KF_LastHResult() -> ultimo HRESULT registrado por KF_Path
HB_FUNC( KF_LASTHRESULT )
{
   hb_retnl( ( long ) s_hrLast );
}

#pragma ENDDUMP

//----------------------------------------------------------------------------//

Cómo probarlo

  1. Compilar con FWH + Harbour y un MinGW con _WIN32_WINNT >= 0x0600, enlazando shell32 y ole32 (SHGetKnownFolderPath y CoTaskMemFree viven ahí). No está probado con otros compiladores ni SDK antiguos.
  2. Pulsar Consultar: aparecen las tres rutas del usuario actual. Como son carpetas por usuario (PERUSER), cambian de un equipo o usuario a otro: comparad entre vosotros y lo veréis.
  3. Mirad el detalle de que la ruta no lleva barra final: al componer un archivo dentro hay que añadirla ("\" + nombre).

Validación del ejemplo (medida, no supuesta)

Compilado sin avisos con Harbour (win64) y FWH 26.10, enlazando shell32 y ole32, ejecutado en Wine 11.19 el 16 de noviembre; la captura adjunta es de esa corrida en Wine (16/11/2026, no Windows nativo). Se pulsó Consultar y las tres rutas aparecieron completas; el cierre fue limpio. Valores observados (16/11/2026):

  • Documentos: C:\users\sandbox\Documents
  • Escritorio: C:\users\sandbox\Desktop
  • Descargas: C:\users\sandbox\Downloads

Las rutas llevan el prefijo del usuario de ese entorno (sandbox). Son carpetas del usuario actual: cada equipo las resuelve para el suyo, siempre que la llamada a la API y la conversión a ANSI tengan éxito.

Manejo de errores: en una variante de prueba (no el ejemplo publicado) se llamó a la función con un identificador de carpeta inválido; el propio wrapper del ejemplo lo rechaza antes de llamar a la API y devolvió NIL con HRESULT -2147024809 (0x80070057, E_INVALIDARG), con el programa respondiendo y cierre limpio. La prueba valida el rechazo de argumento del wrapper y la exposición del HRESULT; no es un fallo devuelto por SHGetKnownFolderPath, cuya rama de error de la propia API no llegó a ejercitarse.

Ojo con los matices:

  • La corrida fue una sola pasada en Wine; en Windows nativo las rutas o el comportamiento pueden diferir y no lo hemos probado.
  • El entorno de pruebas no tenía gestor de ventanas, así que el título de la ventana y el redimensionado no quedaron evaluados.
  • La rama de fallo de la conversión UTF-16 a ANSI del propio programa no llegó a ejercitarse: ninguna conversión falló en estas pruebas. Las tres rutas eran ASCII; una ruta con caracteres no representables en la codepage no queda validada por esta corrida.
  • Resolver estas tres carpetas es evidencia funcional del patrón (GUID más CoTaskMemFree), no una validación de todos los KNOWNFOLDERID del sistema.
  • El ejemplo usa un buffer ANSI fijo de 512 bytes y un campo visible de 345 píxeles. Las rutas de esta prueba caben en ambos; rutas más largas y su visualización completa no quedaron validadas.
