Posted: Sat Jun 27, 2026 04:01 AM

Una implementación libre y de código abierto compatible con Advantage Database Server (ADS), descontinuado por SAP.

https://github.com/FiveTechSoft/OpenADS

El objetivo es proporcionar un reemplazo directo (drop-in replacement) para Advantage Client Engine (ace32.dll / ace64.dll / libace.so), de modo que las aplicaciones existentes —en particular las aplicaciones Harbour/Clipper que utilizan contrib/rddads— sigan funcionando sin necesidad de recompilación.

Una API, muchos motores de base de datos — DBF hoy, cualquier base de datos mañana
OpenADS se presenta como ADS —su aplicación se comunica con los mismos puntos de entrada de ACE que siempre ha usado—, pero esa interfaz de ADS es solo la puerta de entrada. Detrás de ella, esa misma API puede ser atendida por diferentes motores de almacenamiento:

Debido a que la aplicación solo ve la API de ADS, usted puede trabajar con DBF hoy y cambiar a PostgreSQL, MSSQL o SQLite mañana si se queda pequeño para los archivos planos, todo ello sin tener que reescribir su lógica de negocio. El mismo código Harbour/Clipper/FiveWin, las mismas llamadas a USE / dbSeek / tDatabase, ahora respaldados por una base de datos real cuando necesite concurrencia, escalabilidad o administración centralizada. OpenADS es una suite escalable.

Hola Walter,

Hemos revisado el código de OpenADS con tu secuencia exacta y el error tiene explicación concreta. El 5000 es el error interno genérico de la capa ACE de OpenADS, y "unknown table" aparece cuando una función recibe el handle de una tabla MariaDB pero no tiene código para ese backend: entonces lo busca entre las tablas DBF nativas, no lo encuentra y devuelve ese error.

En tu caso:

1) dbAppend() no falla. AdsAppendRecord sí soporta MariaDB: crea el registro pendiente y termina bien. Por eso DbAppend() devuelve NIL pero NetErr() se queda en .F. (buena intuición la de carlos vargas, pero el append no es el que falla).

2) El REPLACE falla en el primer campo numérico o lógico. El RDD llama a una función distinta según el tipo del campo: para carácter usa AdsSetString (que sí soporta MariaDB y funciona), pero para numéricos usa AdsSetDouble/AdsSetLong y para lógicos AdsSetLogical, y esas dos funciones todavía no tienen soporte MariaDB: ahí salta el ADSCDX/5000 "unknown table".

Puedes confirmarlo en un minuto: un REPLACE sobre un campo carácter (o fecha) de esa misma tabla funciona; el mismo REPLACE sobre un campo numérico o lógico da el 5000.

Mientras lo corregimos en la librería, tienes dos caminos:

a) Hacer el alta con SQL en lugar de ISAM: AdsExecuteSQLDirect( "INSERT INTO tabla (campo1, importe, activo) VALUES ('x', 123.45, 1)" )

b) Si prefieres seguir con dbAppend()/REPLACE: limita el REPLACE a campos carácter/fecha y actualiza los campos numéricos y lógicos con un UPDATE por SQL.

Gracias por el reporte tan concreto: con "append + replace sobre MariaDB" el punto de fallo ha quedado localizado en el código.
