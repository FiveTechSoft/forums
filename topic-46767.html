Escribir en la consola del padre desde una aplicación GUI (AttachConsole)

Hola a todos:

Seguimos con la serie de ejemplos de programación Windows con FiveWin. Hoy, una necesidad clásica en los foros de programación: una aplicación compilada como GUI no arranca con una consola asignada (salvo que la herede de su proceso padre o se la asignemos nosotros), pero a veces interesa que escriba en la consola desde la que se lanzó. Sirve para trazas de depuración, mensajes de progreso de procesos por lotes o pequeñas utilidades que conviven entre la ventana y la línea de comandos.

AttachConsole: unirse a una consola existente

La API AttachConsole une nuestro proceso a la consola de otro proceso. Con el valor especial ATTACH_PARENT_PROCESS nos unimos a la consola del proceso que nos lanzó (cmd, PowerShell o un terminal).

No hay que confundirla con AllocConsole: AllocConsole crea una consola nueva y vacía para nuestra aplicación; AttachConsole reutiliza la que ya tiene el padre, de modo que nuestra salida aparece justo donde el usuario lanzó el programa.

Detalles importantes según la documentación de Microsoft:

  • Si el proceso ya tiene una consola, AttachConsole falla con ERROR_ACCESS_DENIED.
  • Si el proceso padre no tiene consola, falla con ERROR_INVALID_HANDLE.
  • Está disponible desde Windows XP.

Para escribir abrimos CONOUT$ con CreateFile en lugar de depender de los handles estándar heredados. Es el mismo enfoque que utiliza el propio driver de consola GT de Harbour (src/rtl/gtwin/gtwin.c).

El ejemplo completo

Una ventana con dos acciones: adjuntarse a la consola del padre y escribir una línea de prueba. El código C embebido es mínimo y va dentro del propio PRG:

Code: Select all Collapse
//----------------------------------------------------------------------------//
// CONSALIDA.PRG (v5)
// Escribir en la consola del proceso padre desde una app GUI (AttachConsole)
// Ejemplo didactico FiveWin (FWH) + Harbour
//
// Que muestra:
//   - AttachConsole(ATTACH_PARENT_PROCESS) desde un PRG con C embebido
//   - Escribir en la consola adjuntada abriendo CONOUT$: el mismo mecanismo
//     que usa el driver de consola GT de Harbour (src/rtl/gtwin/gtwin.c)
//   - Diferencia con AllocConsole: no creamos una consola nueva, nos unimos
//     a la de quien lanzo el exe (cmd, PowerShell, terminal)
//
// v5: Con_WriteLine devuelve .T. solo si AMBOS WriteFile terminan y
// escriben todos los bytes (texto y CRLF); antes bastaba abrir CONOUT$.
// v4: SIZE..PIXEL en el boton Cerrar (sin PIXEL las coordenadas se
// interpretan en unidades de dialogo y el control cae fuera del lienzo).
// v3: +40px de alto y Cerrar mas arriba (Wine sin WM descuenta
// la barra de titulo del rectangulo pedido, no del area cliente).
// v2: ventana TWindow en pixeles reales (patron del ejemplo anterior de la
// serie) en lugar de dialogo de plantilla, para que la geometria no dependa
// de la metrica de fuente del dialogo.
//
// Documentacion de Microsoft:
//   AttachConsole: https://learn.microsoft.com/en-us/windows/console/attachconsole
//   AllocConsole:  https://learn.microsoft.com/en-us/windows/console/allocconsole
//----------------------------------------------------------------------------//

#include "FiveWin.ch"

static cTxtEstado := "Sin comprobar"
static cTxtSalida := "Sin escribir todavia"
static oSayEstado, oSaySalida
static nLinea := 0

//----------------------------------------------------------------------------//

function Main()

   local oWnd

   DEFINE WINDOW oWnd ;
      FROM 0, 0 TO 250, 460 PIXEL ;
      TITLE "Salida a consola desde app GUI (AttachConsole)"

   @ 15, 15 SAY oSayEstado VAR cTxtEstado OF oWnd SIZE 430, 20 PIXEL

   @ 40, 15 SAY oSaySalida VAR cTxtSalida OF oWnd SIZE 430, 20 PIXEL

   @ 70, 15 SAY "Lanza este exe desde cmd, PowerShell o un terminal." OF oWnd SIZE 430, 15 PIXEL

   @ 88, 15 SAY "Despues prueba los botones y mira la consola." OF oWnd SIZE 430, 15 PIXEL

   @ 118, 15 BUTTON "1. Adjuntar a la consola del padre" OF oWnd ;
      SIZE 210, 26 PIXEL ACTION BtnAttach()

   @ 118, 235 BUTTON "2. Escribir linea de prueba" OF oWnd ;
      SIZE 210, 26 PIXEL ACTION BtnWrite()

   @ 156, 180 BUTTON "Cerrar" OF oWnd SIZE 100, 26 PIXEL ACTION oWnd:End()

   ACTIVATE WINDOW oWnd CENTERED

return nil

//----------------------------------------------------------------------------//

static function BtnAttach()

   local nRes := Con_AttachParent()

   do case
      case nRes == 1
         cTxtEstado := "Adjuntada a la consola del proceso padre"
      case nRes == -5
         // ERROR_ACCESS_DENIED: la app ya estaba adjuntada (doc. Microsoft)
         cTxtEstado := "La app ya tenia consola (ERROR_ACCESS_DENIED)"
      case nRes == -6
         // ERROR_INVALID_HANDLE: el padre no tiene consola (doc. Microsoft)
         cTxtEstado := "El proceso padre no tiene consola (ERROR_INVALID_HANDLE)"
      otherwise
         cTxtEstado := "AttachConsole fallo con el error " + ;
                       AllTrim( Str( -nRes ) )
   endcase

   oSayEstado:Refresh()

return nil

//----------------------------------------------------------------------------//

static function BtnWrite()

   nLinea++

   if Con_WriteLine( "Prueba " + AllTrim( Str( nLinea ) ) + ;
                     " desde FiveWin a las " + Time() )
      cTxtSalida := "Linea " + AllTrim( Str( nLinea ) ) + ;
                    " enviada: mirala en la consola"
   else
      cTxtSalida := "La escritura en la consola fallo " + ;
                    "(sin consola adjuntada o error de escritura)"
   endif

   oSaySalida:Refresh()

return nil

//----------------------------------------------------------------------------//

#pragma BEGINDUMP

#include <windows.h>
#include "hbapi.h"

// Con_AttachParent() -> 1 si nos unimos a la consola del proceso padre;
// -GetLastError() si falla (-5 = ya habia consola, -6 = el padre no tiene)
HB_FUNC( CON_ATTACHPARENT )
{
   if( AttachConsole( (DWORD) -1 ) )        // ATTACH_PARENT_PROCESS
      hb_retnl( 1 );
   else
      hb_retnl( - ( long ) GetLastError() );
}

// Con_WriteLine( cTexto ) -> .T. solo si la linea completa se escribio
// en la consola (texto + CRLF, todos los bytes). Abre CONOUT$ (la consola
// adjuntada al proceso) en vez de los handles estandar: el mismo enfoque
// del driver GT de Harbour (gtwin.c).
HB_FUNC( CON_WRITELINE )
{
   HANDLE hOut = CreateFile( "CONOUT$",
                             GENERIC_READ | GENERIC_WRITE,
                             FILE_SHARE_READ | FILE_SHARE_WRITE,
                             NULL, OPEN_EXISTING,
                             FILE_ATTRIBUTE_NORMAL, NULL );
   HB_BOOL bTodo = HB_FALSE;

   if( hOut != INVALID_HANDLE_VALUE )
   {
      DWORD nLen = ( DWORD ) hb_parclen( 1 );
      DWORD nEscritos = 0;
      DWORD nEscritosCrlf = 0;

  if( WriteFile( hOut, hb_parc( 1 ), nLen, &nEscritos, NULL ) &&
      nEscritos == nLen &&
      WriteFile( hOut, "\r\n", 2, &nEscritosCrlf, NULL ) &&
      nEscritosCrlf == 2 )
     bTodo = HB_TRUE;

  CloseHandle( hOut );
   }

   hb_retl( bTodo );
}

#pragma ENDDUMP

//----------------------------------------------------------------------------//

Cómo probarlo

  1. Compilar como cualquier aplicación FWH.
  2. Lanzar el exe desde cmd, PowerShell o un terminal.
  3. Pulsar "1. Adjuntar a la consola del padre" y después "2. Escribir línea de prueba": las líneas "Prueba N desde FiveWin..." aparecen en la consola.

Validación del ejemplo (medida, no supuesta)

Probado con Harbour 3.2.1dev, FWH 26.10 y llvm-mingw, ejecutado en Wine 11.19:

  • Con un lanzador con consola (proceso CUI en un PTY), el botón Adjuntar informa "Adjuntada a la consola del proceso padre" y las líneas de prueba aparecen en el flujo de la consola del padre, confirmadas además leyendo directamente el buffer de la consola (ReadConsoleOutputCharacter).
  • Lanzado desde un proceso padre sin consola, el ejemplo informa "El proceso padre no tiene consola (ERROR_INVALID_HANDLE)" y la escritura falla de forma controlada, tal como documenta Microsoft.

Límites de la prueba: el ensayo se ha hecho en Wine con un lanzador CUI, no en cmd/PowerShell nativos de Windows, y la captura adjunta procede de ese Wine.
