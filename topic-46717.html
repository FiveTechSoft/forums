If your aim is to get a local Harbour project running on Windows without configuring Apache, HIX 2.2 is another option to evaluate: https://github.com/carles9000/hix/releases/tag/v2.2 . If you want to stay with Apache/CGI, send the details above and we can narrow down the executable problem first. I would not call CGI obsolete just because HIX exists.

Dear Dako,

One more point after checking the build files. The repository has a cgi/windows/modharbour.hbp project and a 64-bit build script, but no ready-made 32-bit CGI build script or verified 32-bit CGI download. A 32-bit build appears possible in principle with Harbour for MSVC x86, the x86 Visual Studio toolchain, and matching 32-bit dependencies. This is a route suggested by the project files, not a build we have tested. The windows/go32.bat script in the repository builds the Apache module, not this CGI executable, so please do not run it as a CGI build.

For a new Harbour web project on Windows, we recommend HIX 2.2 instead: https://github.com/carles9000/hix/releases/tag/v2.2 . It is an active project, maintained by its author Carlos Aubia (Charly), whom you can approach for support. mod_harbour remains available, but its community and development have been quiet lately. HIX also avoids the Apache/CGI setup you are troubleshooting.

If you specifically need Apache/CGI, tell us which 32-bit Harbour/MSVC toolchain and libraries you have, and we can help you work through the first build error without claiming a ready-made x86 binary.
