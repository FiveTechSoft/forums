Dear Dako,

Thank you for the details. I checked the official mod_harbour repository: the cgi/windows folder does contain modharbour.exe, but that executable is 64-bit, not 32-bit. You can see the folder and its accompanying x64 DLLs here: https://github.com/FiveTechSoft/mod_harbour/tree/master/cgi/windows . The direct download for that executable is https://raw.githubusercontent.com/FiveTechSoft/mod_harbour/master/cgi/windows/modharbour.exe . Please do not use it as a 32-bit CGI binary.

The Windows message “Unsupported 16-bit Application” does not prove that modharbour is a 16-bit program. To find out what is failing on your machine, could you send us the exact link from which you downloaded your modharbour.exe, its file size, and the full Windows error message? Also tell us whether your Apache installation is 32- or 64-bit. The repository has an older Win32 package under its 2.0 releases, but I cannot confirm that it contains the CGI executable, so I would not recommend it for this setup yet.

CGI and HIX are different approaches. CGI runs under Apache; HIX is a separate Harbour web server. If your aim is to get a local Harbour project running on Windows without configuring Apache, HIX 2.2 is another option to evaluate: https://github.com/carles9000/hix/releases/tag/v2.2 . If you want to stay with Apache/CGI, send the details above and we can narrow down the executable problem first. I would not call CGI obsolete just because HIX exists.

Dear Dako,

One more point after checking the build files. The repository has a cgi/windows/modharbour.hbp project and a 64-bit build script, but no ready-made 32-bit CGI build script or verified 32-bit CGI download. A 32-bit build appears possible in principle with Harbour for MSVC x86, the x86 Visual Studio toolchain, and matching 32-bit dependencies. This is a route suggested by the project files, not a build we have tested. The windows/go32.bat script in the repository builds the Apache module, not this CGI executable, so please do not run it as a CGI build.

For a new Harbour web project on Windows, we recommend HIX 2.2 instead: https://github.com/carles9000/hix/releases/tag/v2.2 . It is an active project, maintained by its author Carlos Aubia (Charly), whom you can approach for support. mod_harbour remains available, but its community and development have been quiet lately. HIX also avoids the Apache/CGI setup you are troubleshooting.

If you specifically need Apache/CGI, tell us which 32-bit Harbour/MSVC toolchain and libraries you have, and we can help you work through the first build error without claiming a ready-made x86 binary.

Please download the executable using the repository's Raw download, not “Save page as” on its GitHub preview:
https://raw.githubusercontent.com/FiveTechSoft/mod_harbour/master/cgi/windows/modharbour.exe

  1. Save it as modharbour.exe and check that its size is 6,042,112 bytes.
  2. Replace the 202 KB file in C:\Apache24\cgi-bin\ with that downloaded file. Keep a copy of the old file outside cgi-bin while testing.
  3. Try your http://localhost/cgi-bin/modharbour.exe?test.prg URL again. If there is another error, please send the exact message and confirm the new file size.

This repository executable is 64-bit, so it is the right architecture to test on 64-bit Windows. The Apache configuration and its own architecture do not, by themselves, explain why a separate CGI executable on disk is only 202 KB.
