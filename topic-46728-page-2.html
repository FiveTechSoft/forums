Dear Jimmy,

Good news, thank you for telling us. The #include "FiveWin.ch" brings in the FWH GUI start-up, which is what the linker was missing.

No, "qr.bmp" is not a resource. QRReadFile() takes the path of a BMP file on disk, and it reads it with normal file functions. I only wrote "qr.bmp" as an example. You can pass any file name or full path, as a parameter or from a variable. For example:

Code: Select all Collapse
#include "FiveWin.ch"

function Main()

   local cFile := cGetFile( "*.bmp", "Select a QR image" )
   local hRes

   if ! Empty( cFile )
      hRes := QRReadFile( cFile )
      if hRes != NIL
         MsgInfo( hRes[ "text" ] )
      else
         MsgInfo( "No QR found" )
      endif
   endif

return nil

Remember that only BMP files are supported by QRReadFile(). If you have a PNG or JPG, convert it to BMP first. If you already have the gray values of an image in memory (for example a frame from a camera), use QRDecodeGray( aGray, nW, nH ) instead.

Dear Jimmy,

The simplest way is in two steps: save the current camera frame as a BMP file with TWebcam, then give that file to QRReadFile(). TWebcam does the capture, and qrread.prg does the decoding. This is based on the TWebcam class and on samples\webcam.prg of FWH, where the "Save Picture" option calls oWebCam:SaveFile().

Code: Select all Collapse
#include "FiveWin.ch"
#include "WebCam.ch"

function Main()

   local oWnd, oWebCam
   local cTmp := hb_DirTemp() + "qrframe.bmp"

   DEFINE WINDOW oWnd TITLE "QR reader with webcam"

   @ 0, 0 WEBCAM oWebCam SIZE 640, 480 OF oWnd START ADJUST RATE 66

   // click on the camera image to read the QR that the camera is showing
   oWebCam:bLClicked := { || ReadQR( oWebCam, cTmp ) }

   ACTIVATE WINDOW oWnd

return nil

static function ReadQR( oWebCam, cTmp )

   local hRes

   FErase( cTmp )
   oWebCam:SaveFile( cTmp )          // saves the current frame as a BMP

   if ! File( cTmp )
      MsgStop( "The frame could not be saved" )
      return nil
   endif

   hRes := QRReadFile( cTmp )

   if hRes != NIL
      MsgInfo( hRes[ "text" ] )
   else
      MsgInfo( "No QR found, try again with more light or closer" )
   endif

return nil

Some tips:

  • Hold the QR code steady, well lit, and big enough in the image. The reader tolerates rotation and some blur, but a very small or out of focus QR will not decode.

  • To read continuously, you can call ReadQR() from a timer (for example every 500 ms) instead of the click, and stop when it returns a text.

  • Remember that qrread.prg must be linked together with this program.

I have not tested this exact program with a real camera, so please tell us what you get. If SaveFile() fails on your PC, tell us the error message.

Dear Jimmy,

You are right, TWebcam is the old AVI style. The current sample samples\misc\dshow.prg uses a new class, TMfWebCam, based on Media Foundation (the C code is embedded in the same PRG, no external DLL needed). The calls we need are in that sample:

  • oCam := TMfWebCam():New( oLive, 66 ) creates the object. oLive is the IMAGE control for the preview (it can be NIL if you do not want a preview).

  • oCam:Connect() opens the camera, oCam:Disconnect() closes it.

  • oCam:Save( NIL, cFile ) saves the current frame. With a ".bmp" file name it writes a 24 bit BMP directly, and it returns .T. or .F.

So the QR reading is the same idea as before: save the frame to a BMP and give that file to QRReadFile(). In dshow.prg, add a button next to the others in Main():

Code: Select all Collapse
   @ nH + 180, nW + 150 BUTTON "Read &QR" OF oDlg SIZE 100, 28 PIXEL ;
      ACTION ReadQR( oCam )

and this function at the end of the PRG:

Code: Select all Collapse
function ReadQR( oCam )

   local cTmp := hb_DirTemp() + "qrframe.bmp"
   local hRes

   FErase( cTmp )

   if ! oCam:Save( NIL, cTmp )        // current frame as BMP
      return nil                      // TMfWebCam already showed the error
   endif

   hRes := QRReadFile( cTmp )

   if hRes != NIL
      MsgInfo( hRes[ "text" ] )
   else
      MsgInfo( "No QR found, try again with more light or closer" )
   endif

return nil

Then build dshow.prg together with qrread.prg (samples\misc\qrread.prg). Hold the QR steady, well lit and big enough in the image. To read continuously, call ReadQR() from a TTimer every 500 ms instead of a button and stop when it finds a text. The same approach works for a barcode on a conveyor belt, as long as you have a decoder for that barcode type: the camera part is only "save the frame, decode the file".

Dear Jimmy,

Here is a first version with a guide frame and continuous scanning, built on samples\misc\dshow.prg (TMfWebCam). A timer saves a frame every 400 ms, calls QRReadFile() on it, and stops at the first QR it decodes. The guide frame is a fixed square in the center of the preview, so the user knows where to hold the code.

In Main() of dshow.prg, change these parts:

Code: Select all Collapse
   local oScan                                  // add to the local list

   // after the IMAGE oLive line: draw the guide frame on top of the preview
   oLive:bPainted := { | hDC | DrawGuide( hDC, nW, nH ) }

   // bInit: start the scan timer after the camera is connected
   oDlg:bInit := {|| SetWindowLong( oDlg:hWnd, GWL_STYLE, ;
                      nOr( GetWindowLong( oDlg:hWnd, GWL_STYLE ), ;
                           WS_CLIPCHILDREN ) ), ;
                     oCam:Connect(), ;
                     oScan := TTimer():New( 400, {|| ScanQR( oCam, oScan ) }, oDlg ), ;
                     oScan:Activate() }

   ACTIVATE DIALOG oDlg CENTERED ;
      VALID ( If( oScan != NIL, oScan:Deactivate(), ), oCam:Disconnect(), .T. )

And add these two functions at the end of the PRG:

Code: Select all Collapse
static function DrawGuide( hDC, nW, nH )

   local nSize := 240
   local nTop  := ( nH - nSize ) / 2
   local nLeft := ( nW - nSize ) / 2
   local hPen  := CreatePen( 0, 3, nRGB( 0, 255, 0 ) )
   local hOldP := SelectObject( hDC, hPen )
   local hOldB := SelectObject( hDC, GetStockObject( 5 ) )   // 5 = NULL_BRUSH, no fill

   Rectangle( hDC, nTop, nLeft, nTop + nSize, nLeft + nSize )

   SelectObject( hDC, hOldB )
   SelectObject( hDC, hOldP )
   DeleteObject( hPen )

return nil

static function ScanQR( oCam, oScan )

   static lBusy := .F.
   local cTmp := hb_DirTemp() + "qrscan.bmp"
   local hRes

   if lBusy .or. ! oCam:isConnected
      return nil
   endif

   lBusy := .T.
   FErase( cTmp )

   if oCam:Save( NIL, cTmp )
      hRes := QRReadFile( cTmp )
      if hRes != NIL
         oScan:Deactivate()               // stop at the first QR found
         MsgInfo( hRes[ "text" ], "QR found" )
      endif
   endif

   lBusy := .F.

return nil

Build it together with qrread.prg, as before.

About the "focus frame" of the iPhone, a frame that follows the QR and then takes the snapshot: this example does not do that. The frame here is a fixed guide, and QRReadFile() analyzes the whole picture, not only the inside of the square. QRReadFile() returns the text, version, error correction level and mask, but not the position of the four corners of the code, and a moving frame needs those corners.
