September 2026

 

  • Fixed: TScrollPanel horizontal scroll (source\classes\scrlpanl.prg). The bGotFocus handler that SetRange() assigns to tab-stop controls called ::ControlIntoView() after a horizontal scroll, pulling the panel back to the focused control. It already skipped this after a vertical scroll; it now skips it after a horizontal scroll too (lHScrolled). No changes required in user code.

 

  • Fixed: IsWindows10() now reads the build number, the same way IsWindows11() does, instead of the registry product name, which says "Windows Server" on server editions: IsWindows10() wrongly returned .F. on Windows Server 2016/2019/2022.

 

  • More tests: the fwunit console suite also covers the credential cipher Encrypt()/Decrypt() (source\internal\encript.c, used by FWMaria connections and FiveDBU) with fixed vectors that pin the algorithm, and the MAPI address-fill toggle SetMapiAddrFill(). The build check now runs the console test suites (fwunit and the offline FWMariaConnection tests) on more build variants, not only on the 32-bit MSVC one.

 

  • Fixed: samples\misc\UTestmnu.prg started with a UTF-8 byte-order mark that the xHarbour compiler rejects (error E0016 at line 1). The BOM is gone; the file stays UTF-8 and builds with Harbour and xHarbour again.

  • Fixed: MAPISendMail() / DEFINE MAIL when TO is given with a single parameter (TO cEmail): the 26.07 fallback copied the bare display name into lpszAddress (no type prefix), which made Outlook build a one-off recipient and Exchange Online never deliver the attachment ("attachment never downloads, try again later"). mapi.c now fills with the typed form SMTP:user@domain and only when the name contains '@' (looks like an e-mail); the bare name is left alone otherwise. New optional SetMapiAddrFill( .F. ) restores the pre-26.07 behaviour of leaving lpszAddress empty for the client to resolve (also disables the typed fill). Dual form TO cName, cAddress is unchanged. Self-registers in Harbour dynsym so hb_IsFunction( "SETMAPIADDRFILL" ) detects it.

    CaseResult
    single[SMTP:someone@example.com]
    dual[someone@example.com] untouched
    SetMapiAddrFill(.F.)address=<NULL>

  • New: TXBrowse cell chart type "GAUGE" (TXBrwColumn:DrawChartInRect, source\classes\xbrowse.prg). Additive mode meant for a cell with a single numeric value, where the classic "BAR" rendering (several side-by-side series) looks like a solid block filling the whole cell. GAUGE draws a thin CLR_HGRAY track with 4px side padding centered vertically (30% insets top/bottom), a proportional fill bar in the series color and a "NN.N%" label painted over it with transparent background. The scale is oCol:nChartMaxVal, automatically raised to the greatest value found. Usage:
    Code: Select all Collapse
    oCol:aChartCols   := { {|| nPct } }
oCol:cChartType   := "GAUGE"
oCol:aChartColors := { CLR_HBLUE }
    "LINE" and "BAR" renderings are unchanged.
    Docs: en/es/pt ui/txbrowse.html#cell-charts.

 

  • New sample: samples\ui\xbrowse\brwfooter.prg + .rc — TXBrowse with footer totals inside a dialog created from a binary resource (CreateFromResource). Enable the footer row with oBrw:lFooter := .T., set nFooterType := AGGR_SUM on the numeric columns, load the data with SetArray( aData, .T. ) BEFORE configuring the columns (SetArray with .T. regenerates aCols) and call MakeTotals(). Two pitfalls documented: the control in the .rc must use window class "TXBrowse" (registered by CreateFromResource; classes like "RichEdit20W" whose DLL is not loaded make DialogBox fail with "Cannot create Dialog Box"), and column data blocks should use oBrw:nArrayAt — not oBrw:nAt — because nAt calls ColAtPos() before ::aDisplay exists during INITIATE/ADJUST. Numeric cell + footer formatting: do NOT set bStrData on numeric array columns. The default bStrData (ArrCell) applies oCol:cEditPicture to data cells; a custom bStrData returning the raw number is shown with plain Str() and the picture is ignored. Totals are unaffected either way because MakeTotals() reads the raw value via bEditValue (::Value), not via bStrData. Use cEditPicture for the cells, cFooterPicture for the footer total (it drops the ".00") and nFootStrAlign to right align it (default is left):
    Code: Select all Collapse
    oCol:cEditPicture   := "999,999,999"
oCol:cFooterPicture := "999,999,999"
oCol:nFootStrAlign  := AL_RIGHT
