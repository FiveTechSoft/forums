From FiveWin to the Web in Less Than 12 Minutes – Is It Time to Rethink Our Strategy?

11 minutes and 52 seconds from the initial analysis to an installed and tested web application.

I think these results deserve the attention of every Harbour and FiveWin developer. AI is fundamentally changing the economics of software development, and we should reconsider our existing migration strategies in light of these new possibilities.

This morning, I conducted a practical experiment following an interesting discussion with Roberto Chiaiese about migrating existing Harbour/FiveWin applications to the web.

The original discussion and the detailed results can be found here:

https://forums.fivetechsupport.com/viewtopic.php?p=287186#p287186

Starting point

I provided Codex with just three existing resources:

  • The XBROWSE example and Harbour microservice that I published a few months ago, including the complete source code.
  • Roberto's original demo application and DBF files.
  • The Harbour source code kindly shared by Roberto.

Development time

MilestoneElapsed time
First successful CRUD test5:04 min
Apache and native DBF record locking verified7:11 min
Browser tests passed9:28 min
All four master data types tested10:52 min
Installed application passed all automated tests11:52 min

These times include analysis, implementation, testing, tool execution and debugging.

The result

A responsive web application in English and Italian, developed with PHP, HTML, CSS and JavaScript.

The existing Harbour microservice remained completely unchanged. Both the desktop application and the web application now access the same DBF files.

  • No custom HTML presentation library.
  • No additional web runtime.
  • No database migration.
  • No modifications to the original desktop application.

Native DBF record locking and conflict detection have been successfully tested.

The generated source code includes extensive English inline comments and technical documentation, making it a potential reference project for other Harbour and FiveWin developers.

Some business rules still need clarification, so this is a working prototype rather than a complete replacement.

Why this matters

For decades, we have developed libraries and frameworks to reduce programming effort. AI is fundamentally changing this equation.

Perhaps we should now focus less on preserving our existing code and more on preserving the decades of business knowledge contained within it.

I believe that anyone planning the future of their Harbour applications should explore these possibilities before committing to a long-term migration strategy.

Ignoring these developments could mean missing one of the greatest opportunities our developer community has had in decades.
