Cifrar datos ligados al usuario o al equipo con DPAPI (CryptProtectData)

Hola a todos:

Seguimos con la serie de ejemplos de programación Windows con FiveWin. Hoy, DPAPI, la Data Protection API de Windows: un par de funciones para cifrar y descifrar buffers ligados al usuario actual o al equipo. Lo veremos con un ejemplo didáctico que cifra y descifra un texto de prueba en memoria, sin guardar nada en disco. Como siempre en esta serie, el objetivo es mostrar la API; cada aplicación tendrá que valorar si encaja en su diseño.

Qué hace DPAPI (y qué no hace)

CryptProtectData cifra un buffer y lo liga a la credencial del usuario actual en ese equipo: típicamente solo ese mismo usuario, en ese mismo equipo, puede descifrarlo con CryptUnprotectData. No gestionamos claves: según la documentación de Microsoft, la propia función crea la clave de sesión a partir de la credencial de inicio de sesión del usuario y la vuelve a derivar al descifrar.

Según la documentación de Microsoft, conviene tener claros sus límites:

  • Excepción documentada: con perfiles móviles (roaming) el usuario puede descifrar sus datos desde otro equipo del dominio.
  • El flag CRYPTPROTECT_LOCAL_MACHINE cambia el ámbito: según la documentación, cualquier usuario de ese equipo puede descifrar el blob. La casilla del ejemplo solo selecciona el flag; el round-trip se hace con el mismo usuario, así que el acceso cruzado entre usuarios no lo probamos aquí.
  • No es una caja fuerte: protege bytes en reposo ligados a la credencial; la documentación indica que puede descifrarlos un usuario con la misma credencial de inicio de sesión.
  • El blob incluye un MAC (comprobación de integridad con clave) para proteger contra la manipulación del dato cifrado.
  • El flujo con CRYPTPROTECT_PROMPTSTRUCT (pedir confirmación al usuario al cifrar/descifrar) está obsoleto y Microsoft anuncia su retirada en feb 2027; aquí pasamos NULL.
  • Disponible desde Windows XP; hay que enlazar crypt32 y liberar el resultado con LocalFree.

El ejemplo completo

Una ventana con un campo de texto (precargado con datos de prueba, no uses datos reales), una casilla para el flag LOCAL_MACHINE y dos acciones: cifrar y descifrar. El código C embebido es mínimo y va dentro del propio PRG:

Code: Select all Collapse
//----------------------------------------------------------------------------//
// DPAPI.PRG (v5)
// v2: la info del blob se muestra en dos SAYs cortos; la linea unica
// con el hex quedaba cortada en el Wine de validacion (430px no dan
// para etiqueta + longitud + 32 caracteres hex).
// v3: SOLO comentarios (precision documental del flag LOCAL_MACHINE y
// del MAC), sin cambios en el codigo ejecutable.
// v4: SOLO comentarios (matiz del fallo de descifrado: no prometer
// deteccion de toda manipulacion), sin cambios en el codigo ejecutable.
// v5: SOLO comentarios (esta nota de versiones), sin cambios en el
// codigo ejecutable. Validado compilando el fuente v4 (mismo codigo
// ejecutable) con Harbour 3.2.1dev + FWH 26.10 + llvm-mingw en
// Wine 11.19 el 4 nov 2026.
// Cifrar y descifrar un texto con DPAPI (CryptProtectData/CryptUnprotectData)
// Ejemplo didactico FiveWin (FWH) + Harbour
//
// Que muestra:
//   - CryptProtectData: cifra un buffer ligandolo a la credencial del
//     usuario actual (o al equipo, con el flag LOCAL_MACHINE)
//   - CryptUnprotectData: lo descifra en las mismas condiciones
//   - El blob cifrado incluye un MAC (comprobacion de integridad con
//     clave) para proteger contra la manipulacion del dato cifrado
//     (doc. Microsoft)
//   - La estructura DATA_BLOB y la liberacion del resultado con LocalFree
//
// Limites documentados por Microsoft (importantes para usarlo bien):
//   - TIPICAMENTE solo lo descifra el mismo usuario en el mismo equipo.
//     Excepcion documentada: con perfil movil (roaming) se puede
//     descifrar desde otro equipo del dominio.
//   - El flag CRYPTPROTECT_LOCAL_MACHINE lo abre a CUALQUIER usuario
//     de ese equipo (doc. Microsoft). El checkbox solo selecciona el
//     flag: el round-trip se hace con el mismo usuario; el acceso
//     cruzado entre usuarios no se prueba en este ejemplo.
//   - No es una caja fuerte: protege bytes en reposo ligados a la
//     credencial; la doc. indica que puede descifrarlos un usuario
//     con la misma credencial de inicio de sesion.
//   - El flujo con CRYPTPROTECT_PROMPTSTRUCT esta obsoleto y Microsoft
//     anuncia su retirada en feb 2027: aqui pasamos NULL.
//
// USA SOLO DATOS DE PRUEBA: este ejemplo no guarda nada en disco.
//
// Documentacion de Microsoft:
//   CryptProtectData:   https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata
//   CryptUnprotectData: https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptunprotectdata
//   Ejemplo MS en C:    https://learn.microsoft.com/en-us/windows/win32/seccrypto/example-c-program-using-cryptprotectdata
//
// Compilar enlazando crypt32: -lcrypt32
//----------------------------------------------------------------------------//

#include "FiveWin.ch"

static cTxtEntrada  := "Texto de prueba DPAPI 12345"
static lLocalMachine := .F.
static cBlob        := ""   // blob cifrado (binario), solo en memoria
static cTxtEstado   := "Sin cifrar todavia"
static cTxtBlob     := ""
static cTxtHex      := ""
static cTxtDesc     := ""
static oGet, oSayEstado, oSayBlob, oSayHex, oSayDesc, oChk

//----------------------------------------------------------------------------//

function Main()

   local oWnd

   DEFINE WINDOW oWnd ;
      FROM 0, 0 TO 380, 460 PIXEL ;
      TITLE "DPAPI: CryptProtectData / CryptUnprotectData"

   @ 15, 15 SAY "DPAPI cifra datos ligados a la credencial del usuario" OF oWnd SIZE 430, 15 PIXEL

   @ 33, 15 SAY "actual (o al equipo entero). Usa SOLO datos de prueba." OF oWnd SIZE 430, 15 PIXEL

   @ 62, 15 SAY "Texto a cifrar:" OF oWnd SIZE 430, 15 PIXEL

   @ 80, 15 GET oGet VAR cTxtEntrada OF oWnd SIZE 430, 22 PIXEL

   @ 112, 15 CHECKBOX oChk VAR lLocalMachine ;
      PROMPT "LOCAL_MACHINE: cualquier usuario de ESTE equipo podra descifrar" ;
      OF oWnd SIZE 430, 18 PIXEL

   @ 142, 15 BUTTON "1. Cifrar (CryptProtectData)" OF oWnd ;
      SIZE 210, 26 PIXEL ACTION BtnCifrar()

   @ 142, 235 BUTTON "2. Descifrar (CryptUnprotectData)" OF oWnd ;
      SIZE 210, 26 PIXEL ACTION BtnDescifrar()

   @ 180, 15 SAY oSayEstado VAR cTxtEstado OF oWnd SIZE 430, 20 PIXEL

   @ 203, 15 SAY oSayBlob VAR cTxtBlob OF oWnd SIZE 430, 20 PIXEL

   @ 226, 15 SAY oSayHex VAR cTxtHex OF oWnd SIZE 430, 20 PIXEL

   @ 249, 15 SAY oSayDesc VAR cTxtDesc OF oWnd SIZE 430, 20 PIXEL

   @ 282, 180 BUTTON "Cerrar" OF oWnd SIZE 100, 26 PIXEL ACTION oWnd:End()

   ACTIVATE WINDOW oWnd CENTERED

return nil

//----------------------------------------------------------------------------//

static function BtnCifrar()

   local cRes

   oGet:Refresh()   // vuelca lo editado al VAR

   if Empty( cTxtEntrada )
      cTxtEstado := "Escribe primero un texto de prueba"
      cTxtBlob   := ""
      cTxtHex    := ""
      cTxtDesc   := ""
   else
      cRes := DPAPI_Protect( cTxtEntrada, lLocalMachine )
      if cRes == NIL
         cTxtEstado := "CryptProtectData fallo (error " + ;
                       AllTrim( Str( DPAPI_LastError() ) ) + ")"
         cTxtBlob   := ""
         cTxtHex    := ""
         cTxtDesc   := ""
      else
         cBlob      := cRes
         cTxtEstado := "Cifrado OK, ambito: " + ;
                       iif( lLocalMachine, "equipo (LOCAL_MACHINE)", ;
                                            "solo este usuario" )
         cTxtBlob   := "Blob cifrado: " + AllTrim( Str( Len( cBlob ) ) ) + ;
                       " bytes"
         cTxtHex    := "Hex primeros bytes: " + ;
                       Left( hb_StrToHex( cBlob ), 24 )
         cTxtDesc   := "Pulsa 2 para descifrarlo"
      endif
   endif

   oSayEstado:Refresh()
   oSayBlob:Refresh()
   oSayHex:Refresh()
   oSayDesc:Refresh()

return nil

//----------------------------------------------------------------------------//

static function BtnDescifrar()

   local cRes

   if Empty( cBlob )
      cTxtEstado := "Cifra un texto primero"
      cTxtBlob   := ""
      cTxtDesc   := ""
   else
      cRes := DPAPI_Unprotect( cBlob )
      if cRes == NIL
         // Un fallo puede deberse a contexto incompatible (otro usuario
         // o equipo) o a datos alterados; consultar el error devuelto
         cTxtEstado := "CryptUnprotectData fallo (error " + ;
                       AllTrim( Str( DPAPI_LastError() ) ) + ")"
         cTxtDesc   := "Otro usuario/equipo, o blob alterado, no descifra"
      else
         cTxtEstado := "Descifrado OK por el mismo usuario y equipo"
         cTxtDesc   := "Texto recuperado: " + cRes
      endif
   endif

   oSayEstado:Refresh()
   oSayDesc:Refresh()

return nil

//----------------------------------------------------------------------------//

#pragma BEGINDUMP

#include <windows.h>
#include <dpapi.h>
#include "hbapi.h"

// Ultimo GetLastError() de CryptProtectData/CryptUnprotectData
static DWORD s_dwLastError = 0;

// DPAPI_Protect( cDatos, lLocalMachine ) -> cBlobCifrado (binario) o NIL
// DATA_BLOB de entrada: { cbData, pbData }; el de salida lo rellena
// CryptProtectData y se libera con LocalFree (doc. Microsoft).
// Flags: 0 = solo este usuario en este equipo;
//        CRYPTPROTECT_LOCAL_MACHINE = cualquier usuario de este equipo.
// pPromptStruct = NULL: el flujo con prompt esta obsoleto (retirada feb 2027).
HB_FUNC( DPAPI_PROTECT )
{
   DATA_BLOB blobIn, blobOut;
   DWORD dwFlags = 0;

   blobIn.pbData = ( BYTE * ) hb_parc( 1 );
   blobIn.cbData = ( DWORD ) hb_parclen( 1 );

   if( hb_parl( 2 ) )
      dwFlags |= CRYPTPROTECT_LOCAL_MACHINE;

   if( CryptProtectData( &blobIn, NULL, NULL, NULL, NULL,
                         dwFlags, &blobOut ) )
   {
      hb_retclen( ( const char * ) blobOut.pbData, blobOut.cbData );
      LocalFree( blobOut.pbData );
      s_dwLastError = 0;
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
   }
}

// DPAPI_Unprotect( cBlobCifrado ) -> cTextoOriginal o NIL
// Misma estructura DATA_BLOB; el resultado tambien se libera con LocalFree.
HB_FUNC( DPAPI_UNPROTECT )
{
   DATA_BLOB blobIn, blobOut;

   blobIn.pbData = ( BYTE * ) hb_parc( 1 );
   blobIn.cbData = ( DWORD ) hb_parclen( 1 );

   if( CryptUnprotectData( &blobIn, NULL, NULL, NULL, NULL,
                           0, &blobOut ) )
   {
      hb_retclen( ( const char * ) blobOut.pbData, blobOut.cbData );
      LocalFree( blobOut.pbData );
      s_dwLastError = 0;
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
   }
}

// DPAPI_LastError() -> ultimo GetLastError() de las dos funciones
HB_FUNC( DPAPI_LASTERROR )
{
   hb_retnl( ( long ) s_dwLastError );
}

#pragma ENDDUMP

//----------------------------------------------------------------------------//

Cómo probarlo

  1. Compilar como cualquier aplicación FWH, enlazando crypt32 (-lcrypt32).
  2. Escribir un texto de prueba y pulsar "1. Cifrar": aparecen la longitud del blob y sus primeros bytes en hexadecimal.
  3. Pulsar "2. Descifrar": se recupera el texto original.
  4. Marcar la casilla LOCAL_MACHINE y repetir: el ámbito declarado del cifrado pasa a ser todo el equipo.

Validación del ejemplo (medida, no supuesta)

Probado con Harbour 3.2.1dev (r2608271822), FWH 26.10 (FW_VersionNo 26080), llvm-mingw 20261020 (UCRT), ejecutado en Wine 11.19:

  • Con el texto sintético precargado "Texto de prueba DPAPI 12345", CryptProtectData devolvió un blob de 170 bytes y CryptUnprotectData recuperó el texto exacto, tanto en ámbito usuario como con el flag LOCAL_MACHINE (capturas adjuntas, tomadas en ese Wine).
  • Detalle medido: los primeros bytes del blob en esta prueba son 01 00 00 00 seguidos de la cadena "Wine Cry", la firma del proveedor DPAPI de Wine. No hemos comprobado el formato interno del blob en Windows nativo ni lo damos por conocido; lo portable es la pareja de funciones, no el formato interno.
  • La interacción con la ventana en el ensayo fue por teclado (Tab+Space): los clics sintéticos no activaron los botones en ese entorno de pruebas, con causa no determinada. Es una observación del montaje del ensayo, no del ejemplo.

Límites de la prueba: el ensayo se hizo en Wine con un único usuario, así que el round-trip demuestra la recuperación del texto de prueba en ese Wine, no es una garantía de seguridad. El rechazo al descifrar desde otro usuario o equipo es el comportamiento que documenta Microsoft; no lo hemos inducido en esta prueba.
