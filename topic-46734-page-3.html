He preparado una prueba de diagnóstico sobre tu ejemplo original del primer post. Conserva FOLDER, controles, posiciones y orden. No es un arreglo: busca separar el foco real de su indicador visual, sin volver a pedirte SetForegroundWindow/SetFocus ni el mensaje 295/196610 que ya no funcionaron.

Comprobación realizada
El original y esta variante compilan y enlazan sin errores ni avisos con Harbour/FWH64 y mingw64/clang. En Wine 11.19 comprobamos creación del log, cambios de foco al recorrer con TAB, segunda vuelta y cierre normal con STOP al final. La prueba usó TAB sintético; no reprodujo la diferencia entre doble clic y Enter. Allí ui=0: eso NO descarta lo que ocurre en tu Windows. No está probado en Windows real, xHarbour ni tu compilador.

Cómo compararlo en tu Windows

  1. Comprueba primero el original sin registro, para confirmar que sigue el síntoma.
  2. Compila este PRG completo con tu build habitual de FWH/Harbour, sin añadir el workaround de flechas ni MsgInfo.
  3. Abre el mismo EXE con doble clic. Recorre los controles con TAB, dejando aproximadamente un segundo en cada uno, y da una segunda vuelta. Anota dónde ves o no el punteado y cierra con Ok.
  4. Abre el mismo EXE seleccionándolo y pulsandoEnter. Repite el recorrido y cierre.
  5. Abre la carpeta temporal con Win+R, escribe %TEMP% y busca los dos archivos carlos_focus_*.log. El nombre incluye PID y tiempo para separarlos. Indica cuál corresponde a cada modo de arranque. Si la compilación falla con tu kit, basta el error exacto y qué Harbour/compilador usas; no hace falta cambiar tu aplicación.

Qué registra y qué no
focus identifica el HWND que tiene el foco; cada fila permite relacionarlo con su clase e ID. En ui, el bit 1 significa indicador de foco oculto y el bit 2 aceleradores ocultos; pueden combinarse con otros bits. No registra el texto de los campos ni las teclas pulsadas.

Es muestreo, no una traza de cada TAB: puede perder estados intermedios y el propio registro altera el tiempo de ejecución. Si al instrumentarlo desaparece el síntoma, dínoslo: no lo tomaremos como una corrección. Con los dos resultados podremos decidir qué medir después sin trasladar una flecha simulada a todos los diálogos.

static void cvf_window( HWND h )
{
   char cls[128], row[512];

   if( ! IsWindow( h ) ) return;

      " hwnd=%p parent=%p id=%d class=%s ui=%lu visible=%d enabled=%d\n",

      (unsigned long) SendMessage(h,WM_QUERYUISTATE,0,0),
      IsWindowVisible(h), IsWindowEnabled(h) );
   if( n > 0 && (size_t)n < sizeof(row) && cvf_used + n + 1 < sizeof(cvf_now) )

      memcpy(cvf_now+cvf_used,row,n); cvf_used += n; cvf_now[cvf_used]=0;
   }
}
static BOOL CALLBACK cvf_enum( HWND h, LPARAM unused )
{
   (void) unused; cvf_window(h); return TRUE;
}
static void cvf_sample( void )
{
   DWORD tick;
   if( !cvf_log || !IsWindow(cvf_root) ) return;
   tick = GetTickCount();
   cvf_used = (size_t)snprintf(cvf_now,sizeof(cvf_now),
      "focus=%p foreground=%p root=%p\n", (void *)GetFocus(),
      (void *)GetForegroundWindow(),(void *)cvf_root);
   cvf_window(cvf_root);
   EnumChildWindows(cvf_root,cvf_enum,0);
   if( strcmp(cvf_now,cvf_prev) != 0 || tick-cvf_lastwrite >= 1000 )
   {
      fprintf(cvf_log,"t_ms=%lu\n%s\n",(unsigned long)(tick-cvf_start),cvf_now);
      fflush(cvf_log); strcpy(cvf_prev,cvf_now); cvf_lastwrite=tick;
   }
}
static VOID CALLBACK cvf_tick( HWND h, UINT m, UINT_PTR id, DWORD tick )
{
   (void)h;(void)m;(void)id;(void)tick; cvf_sample();
}
