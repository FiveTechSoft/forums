Fecha y hora según el locale con las APIs Ex

Hola a todos:

Seguimos con la serie de ejemplos de programación Windows con FiveWin. Hoy, tres APIs que conviene conocer si la aplicación se mueve entre idiomas: GetLocaleInfoEx, GetDateFormatEx y GetTimeFormatEx. Las clásicas GetLocaleInfo/GetDateFormat identifican el locale con un LCID numérico; las versiones Ex, disponibles desde Windows Vista, lo identifican por su nombre ("es-ES", "en-US"...), que es la forma recomendada por Microsoft, y trabajan en Unicode (UTF-16).

Lo que dice la documentación de Microsoft

  • GetLocaleInfoEx devuelve los formatos del locale sin formatear nada: LOCALE_SSHORTDATE, LOCALE_SLONGDATE y LOCALE_STIMEFORMAT son las constantes para los formatos de fecha corta, fecha larga y hora.
  • GetDateFormatEx formatea una fecha con el formato del locale (DATE_LONGDATE, DATE_SHORTDATE) o con un "picture" propio (por ejemplo dddd, d MMMM yyyy); los nombres de día y mes salen en el idioma del locale aunque el picture sea fijo.
  • GetTimeFormatEx hace lo propio con la hora; admite pictures (hh, mm, ss, tt) y flags como TIME_FORCE24HOURFORMAT.
  • El locale puede darse por nombre o con valores predefinidos como LOCALE_NAME_USER_DEFAULT.
  • Los datos regionales pueden variar entre equipos y versiones (locales personalizados, cambios de datos): no conviene persistirlos como si fueran constantes.
  • Requieren Windows Vista o superior; al compilar, el SDK debe definir _WIN32_WINNT >= 0x0600. Las tres APIs viven en kernel32: usarlas no añade ninguna biblioteca a la aplicación.

El ejemplo completo

Una ventana con cinco botones de locale (es-ES, en-US, de-DE, fr-FR, it-IT). Al pulsar uno se rellenan siete valores: los tres formatos leídos con GetLocaleInfoEx y cuatro cadenas formateadas con GetDateFormatEx (fecha larga, fecha corta y el picture dddd, d MMMM yyyy) y GetTimeFormatEx. El código C embebido va en el propio PRG. Ojo a un detalle: el programa es ANSI y convierte el resultado UTF-16 a la codepage del sistema (CP_ACP); un nombre que no quepa en esa codepage se vería como "?" en pantalla. Es una limitación del programa, no de la API. Las conversiones se comprueban: si una falla, o si falla la propia API (por ejemplo, un nombre de locale inválido), el campo muestra el código de error en lugar de quedarse en blanco.

//----------------------------------------------------------------------------//
// LOCALEEX.PRG (v2)
// Fecha y hora segun locale con las APIs Ex: GetLocaleInfoEx,
// GetDateFormatEx y GetTimeFormatEx
// Ejemplo didactico FiveWin (FWH) + Harbour
//
// Que muestra:
//   - Las APIs Ex reciben el locale por NOMBRE ("es-ES", "en-US"...),
//     no por LCID numerico como las clasicas GetLocaleInfo/GetDateFormat
//     (doc. Microsoft)
//   - GetLocaleInfoEx: lee los formatos del locale sin formatear nada
//     (LOCALE_SSHORTDATE, LOCALE_SLONGDATE, LOCALE_STIMEFORMAT)
//   - GetDateFormatEx/GetTimeFormatEx: formatean la fecha/hora actual
//     con el formato del locale (DATE_LONGDATE, DATE_SHORTDATE) o con
//     un "picture" propio (dddd, d MMMM yyyy)
//   - Son las funciones recomendadas desde Windows Vista frente a las
//     clasicas; devuelven cadenas UTF-16 (doc. Microsoft)
//
// Este programa es ANSI: convierte el resultado UTF-16 a la codepage
// del sistema (CP_ACP). Un nombre de dia o de mes que no quepa en esa
// codepage se vera como "?" en pantalla; es una limitacion del
// programa, no de la API.
//
// Los datos regionales pueden variar entre equipos y versiones (doc.
// Microsoft); lo que se ve en pantalla es lo que devuelve este equipo.
//
// Requiere Windows Vista o superior; al compilar, el SDK debe definir
// _WIN32_WINNT >= 0x0600 (doc. Microsoft). Las APIs viven en kernel32:
// no necesitan librerias extra al enlazar.
//
// v2: ToWide/ToAnsi devolvian el texto sin mirar si la conversion
// habia fallado, y un fallo de WideCharToMultiByte dejaba a hb_retc
// con un buffer sin inicializar. Ahora ambas devuelven exito/fracaso
// (y dejan el buffer terminado en nulo si fallan) y cada funcion
// comprueba la conversion antes de usarla: un fallo se reporta como
// cualquier otro error. Mismo comportamiento cuando todo va bien.
//
// Documentacion de Microsoft:
//   https://learn.microsoft.com/en-us/windows/win32/api/winnls/nf-winnls-getlocaleinfoex
//   https://learn.microsoft.com/en-us/windows/win32/api/datetimeapi/nf-datetimeapi-getdateformatex
//   https://learn.microsoft.com/en-us/windows/win32/api/datetimeapi/nf-datetimeapi-gettimeformatex
//----------------------------------------------------------------------------//

#include "FiveWin.ch"

static cLocale := ""
static oSayEstado
static oSayCorto, oSayLargo, oSayFmtHora
static oSayFecLarga, oSayFecCorta, oSayFecPic, oSayHora

//----------------------------------------------------------------------------//

function Main()

   local oWnd

   DEFINE WINDOW oWnd ;
      FROM 0, 0 TO 440, 520 PIXEL ;
      TITLE "Fecha y hora segun locale (APIs Ex)"

   @ 15, 15 SAY "Las APIs Ex formatean fecha y hora para un locale dado por su" OF oWnd SIZE 490, 15 PIXEL

   @ 33, 15 SAY "nombre (es-ES, en-US...), no por LCID numerico (doc. Microsoft)." OF oWnd SIZE 490, 15 PIXEL

   @ 70, 15 BUTTON "es-ES" OF oWnd ;
      SIZE 92, 26 PIXEL ACTION BtnLocale( "es-ES" )

   @ 70, 113 BUTTON "en-US" OF oWnd ;
      SIZE 92, 26 PIXEL ACTION BtnLocale( "en-US" )

   @ 70, 211 BUTTON "de-DE" OF oWnd ;
      SIZE 92, 26 PIXEL ACTION BtnLocale( "de-DE" )

   @ 70, 309 BUTTON "fr-FR" OF oWnd ;
      SIZE 92, 26 PIXEL ACTION BtnLocale( "fr-FR" )

   @ 70, 407 BUTTON "it-IT" OF oWnd ;
      SIZE 92, 26 PIXEL ACTION BtnLocale( "it-IT" )

   @ 112, 15 SAY "Formatos del locale (GetLocaleInfoEx):" OF oWnd SIZE 490, 15 PIXEL

   @ 134, 15 SAY "Fecha corta:" OF oWnd SIZE 210, 18 PIXEL
   @ 134, 230 SAY oSayCorto PROMPT "" OF oWnd SIZE 275, 18 PIXEL

   @ 156, 15 SAY "Fecha larga:" OF oWnd SIZE 210, 18 PIXEL
   @ 156, 230 SAY oSayLargo PROMPT "" OF oWnd SIZE 275, 18 PIXEL

   @ 178, 15 SAY "Hora:" OF oWnd SIZE 210, 18 PIXEL
   @ 178, 230 SAY oSayFmtHora PROMPT "" OF oWnd SIZE 275, 18 PIXEL

   @ 212, 15 SAY "Hoy formateado (GetDateFormatEx / GetTimeFormatEx):" OF oWnd SIZE 490, 15 PIXEL

   @ 234, 15 SAY "Fecha larga:" OF oWnd SIZE 210, 18 PIXEL
   @ 234, 230 SAY oSayFecLarga PROMPT "" OF oWnd SIZE 275, 18 PIXEL

   @ 256, 15 SAY "Fecha corta:" OF oWnd SIZE 210, 18 PIXEL
   @ 256, 230 SAY oSayFecCorta PROMPT "" OF oWnd SIZE 275, 18 PIXEL

   @ 278, 15 SAY "Picture dddd, d MMMM yyyy:" OF oWnd SIZE 210, 18 PIXEL
   @ 278, 230 SAY oSayFecPic PROMPT "" OF oWnd SIZE 275, 18 PIXEL

   @ 300, 15 SAY "Hora:" OF oWnd SIZE 210, 18 PIXEL
   @ 300, 230 SAY oSayHora PROMPT "" OF oWnd SIZE 275, 18 PIXEL

   @ 334, 15 SAY oSayEstado PROMPT "" OF oWnd SIZE 490, 18 PIXEL

   @ 360, 210 BUTTON "Cerrar" OF oWnd ;
      SIZE 100, 26 PIXEL ACTION oWnd:End()

   ACTIVATE WINDOW oWnd CENTERED

return nil

//----------------------------------------------------------------------------//

static function BtnLocale( cNuevo )

   cLocale := cNuevo
   Refrescar()

return nil

//----------------------------------------------------------------------------//

static function Refrescar()

   PonerValor( oSayCorto,    LX_Info( cLocale, 0 ) )
   PonerValor( oSayLargo,    LX_Info( cLocale, 1 ) )
   PonerValor( oSayFmtHora,  LX_Info( cLocale, 2 ) )
   PonerValor( oSayFecLarga, LX_FormatDate( cLocale, 0 ) )
   PonerValor( oSayFecCorta, LX_FormatDate( cLocale, 1 ) )
   PonerValor( oSayFecPic,   LX_FormatDate( cLocale, 2 ) )
   PonerValor( oSayHora,     LX_FormatTime( cLocale ) )

   oSayEstado:SetText( "Locale activo: " + cLocale + ;
                       " (lo mostrado es lo devuelto por este equipo)" )

return nil

//----------------------------------------------------------------------------//

static function PonerValor( oSay, cValor )

   if cValor == NIL
      oSay:SetText( "(error " + ;
                    AllTrim( Str( LX_LastError() ) ) + ")" )
   else
      oSay:SetText( cValor )
   endif

return nil

//----------------------------------------------------------------------------//

#pragma BEGINDUMP

#include <windows.h>
#include "hbapi.h"

// Ultimo GetLastError() de las LX_*
static DWORD s_dwLastError = 0;

// Harbour (ANSI) -> UTF-16. Devuelve 1 si convierte, 0 si falla;
// en caso de fallo deja el buffer terminado en nulo.
static int ToWide( const char *szAnsi, WCHAR *wBuf, int cch )
{
   int nRes = MultiByteToWideChar( CP_ACP, 0, szAnsi, -1, wBuf, cch );

   if( nRes == 0 )
   {
      wBuf[ 0 ] = L'\0';
      return 0;
   }

   return 1;
}

// UTF-16 -> Harbour (ANSI, codepage del sistema). Devuelve 1 si
// convierte, 0 si falla; en caso de fallo deja el buffer terminado
// en nulo.
static int ToAnsi( const WCHAR *wBuf, char *szBuf, int cb )
{
   int nRes = WideCharToMultiByte( CP_ACP, 0, wBuf, -1, szBuf, cb,
                                   NULL, NULL );

   if( nRes == 0 )
   {
      szBuf[ 0 ] = '\0';
      return 0;
   }

   return 1;
}

// LX_Info( cLocale, nItem ) -> cValor o NIL
// nItem: 0 = formato de fecha corta, 1 = fecha larga, 2 = hora.
// Lee el formato sin formatear nada (doc. Microsoft).
HB_FUNC( LX_INFO )
{
   WCHAR wLocale[ 64 ];
   WCHAR wBuf[ 256 ];
   char  szBuf[ 512 ];
   LCTYPE lcType;
   int nRes;

   switch( hb_parni( 2 ) )
   {
      case 0: lcType = LOCALE_SSHORTDATE;  break;
      case 1: lcType = LOCALE_SLONGDATE;   break;
      case 2: lcType = LOCALE_STIMEFORMAT; break;
      default:
         s_dwLastError = 87;   // ERROR_INVALID_PARAMETER
         hb_ret();
         return;
   }

   if( ! ToWide( hb_parc( 1 ), wLocale, 64 ) )
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
      return;
   }

   nRes = GetLocaleInfoEx( wLocale, lcType, wBuf, 256 );

   if( nRes > 0 )
   {
      if( ! ToAnsi( wBuf, szBuf, sizeof( szBuf ) ) )
      {
         s_dwLastError = GetLastError();
         hb_ret();   // NIL
         return;
      }
      hb_retc( szBuf );
      s_dwLastError = 0;
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
   }
}

// LX_FormatDate( cLocale, nModo ) -> cFecha o NIL
// nModo: 0 = DATE_LONGDATE, 1 = DATE_SHORTDATE,
//        2 = picture propio "dddd, d MMMM yyyy" (dwFlags a 0).
HB_FUNC( LX_FORMATDATE )
{
   WCHAR wLocale[ 64 ];
   WCHAR wBuf[ 256 ];
   char  szBuf[ 512 ];
   SYSTEMTIME st;
   DWORD dwFlags = 0;
   const WCHAR *wPicture = NULL;
   int nRes;

   switch( hb_parni( 2 ) )
   {
      case 0: dwFlags = DATE_LONGDATE;               break;
      case 1: dwFlags = DATE_SHORTDATE;              break;
      case 2: wPicture = L"dddd, d MMMM yyyy";       break;
      default:
         s_dwLastError = 87;   // ERROR_INVALID_PARAMETER
         hb_ret();
         return;
   }

   if( ! ToWide( hb_parc( 1 ), wLocale, 64 ) )
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
      return;
   }

   GetLocalTime( &st );

   nRes = GetDateFormatEx( wLocale, dwFlags, &st, wPicture, wBuf, 256, NULL );

   if( nRes > 0 )
   {
      if( ! ToAnsi( wBuf, szBuf, sizeof( szBuf ) ) )
      {
         s_dwLastError = GetLastError();
         hb_ret();   // NIL
         return;
      }
      hb_retc( szBuf );
      s_dwLastError = 0;
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
   }
}

// LX_FormatTime( cLocale ) -> cHora o NIL
// Sin picture ni flags: el formato de hora del locale tal cual.
HB_FUNC( LX_FORMATTIME )
{
   WCHAR wLocale[ 64 ];
   WCHAR wBuf[ 128 ];
   char  szBuf[ 256 ];
   SYSTEMTIME st;
   int nRes;

   if( ! ToWide( hb_parc( 1 ), wLocale, 64 ) )
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
      return;
   }

   GetLocalTime( &st );

   nRes = GetTimeFormatEx( wLocale, 0, &st, NULL, wBuf, 128 );

   if( nRes > 0 )
   {
      if( ! ToAnsi( wBuf, szBuf, sizeof( szBuf ) ) )
      {
         s_dwLastError = GetLastError();
         hb_ret();   // NIL
         return;
      }
      hb_retc( szBuf );
      s_dwLastError = 0;
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
   }
}

// LX_LastError() -> ultimo GetLastError() de las LX_*
HB_FUNC( LX_LASTERROR )
{
   hb_retnl( ( long ) s_dwLastError );
}

#pragma ENDDUMP

//----------------------------------------------------------------------------//

Cómo probarlo

  1. Compilar con FWH + Harbour y un MinGW con _WIN32_WINNT >= 0x0600. Estas tres APIs están en kernel32, así que no hay que enlazar ninguna biblioteca adicional por ellas (más allá de las habituales de una aplicación FiveWin). No está probado con otros compiladores ni SDK antiguos.
  2. Pulsar cada botón de locale y comparar: los formatos cambian (M/d/yyyy frente a d/M/yyyy, el marcador AM/PM de en-US frente al formato 24 horas) y los textos formateados siguen al idioma correspondiente.
  3. El picture fijo "dddd, d MMMM yyyy" mantiene la estructura, pero los nombres salen en el idioma del locale: es la diferencia entre fijar el formato y fijar el idioma.

Validación del ejemplo (medida, no supuesta)

Compilado sin avisos con Harbour (win64) y FWH 26.10, ejecutado en Wine 11.19 el 13 de noviembre; las capturas adjuntas proceden de esa corrida en Wine. Se pulsaron los cinco botones sin errores y el cierre fue limpio. Valores observados (13/11/2026, viernes, 12:41):

  • es-ES: formatos d/M/yyyy, dddd, d 'de' MMMM 'de' yyyy y H:mm:ss; "viernes, 13 de noviembre de 2026", 13/11/2026, "viernes, 13 noviembre 2026", 12:41:32.
  • en-US: formatos M/d/yyyy, dddd, MMMM d, yyyy y h:mm:ss tt; "Friday, November 13, 2026", 11/13/2026, "Friday, 13 November 2026", 12:41:34 PM.
  • de-DE: formatos d.M.yyyy, dddd, d. MMMM yyyy y HH:mm:ss; "Freitag, 13. November 2026", 13.11.2026, "Freitag, 13 November 2026", 12:41:36.
  • fr-FR: formatos dd/MM/yyyy, dddd d MMMM yyyy y HH:mm:ss; "vendredi 13 novembre 2026", 13/11/2026, "vendredi, 13 novembre 2026", 12:41:38.
  • it-IT: formatos dd/MM/yyyy, dddd d MMMM yyyy y HH:mm:ss; "venerdì 13 novembre 2026", 13/11/2026, "venerdì, 13 novembre 2026", 12:41:40.

Detalle didáctico de la corrida: con fecha 13/11/2026 la fecha corta deja ver quién es quién (13/11 en es-ES frente a 11/13 en en-US); con otras fechas (11/11, por ejemplo) saldrían idénticas y solo la fila de formatos desambiguaría.

Manejo de errores: en una variante de prueba (no el ejemplo publicado) se cambió un botón a un nombre de locale inválido; las siete etiquetas mostraron el código de error 87 (ERROR_INVALID_PARAMETER, devuelto por las APIs Ex) sin bloqueos y con cierre limpio.

Ojo con los matices:

  • Los formatos vienen de la base de datos de locales de ese Wine; en Windows nativo pueden ser distintos y no lo hemos probado.
  • La rama de fallo de las conversiones ANSI/UTF-16 del propio programa no llegó a ejercitarse: ninguna conversión falló en estas pruebas.
  • En estos cinco locales latinos no apareció ningún "?" por la conversión ANSI; con alfabetos no latinos podría aparecer, y tampoco lo hemos probado. La codepage ANSI concreta de ese Wine no se identificó.
