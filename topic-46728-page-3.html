Dear Jimmy,

Thank you for pasting it. Your dshow.prg is the older DirectShow version (a TControl linked to the "ActiveMovie Window" and a photo taken with oCamera:SaveToBmp()). It is a different file from the one in the current FWH build, so my previous example does not fit it. For your file the idea is the same, but simpler: a timer calls oCamera:SaveToBmp(), then QRReadFile(), and stops at the first QR found.

In your Main(), change it like this:

Code: Select all Collapse
function Main()

   local oWnd, hWnd, oCamera, pMediaControl, oScan

   DEFINE WINDOW oWnd

   oCamera = TControl()

   oCamera:bLClicked = { || TakePhoto( oCamera ) }

   ACTIVATE WINDOW oWnd MAXIMIZED ;
      ON INIT ( pMediaControl := DShowCamera(),;
                SetParent( hWnd := FindWindow( 0, "ActiveMovie Window" ), oWnd:hWnd ),;
                SetWindowLong( hWnd, GWL_STYLE, nOr( WS_CHILD, WS_VISIBLE ) ),;
                SetWindowPos( hWnd, 0, 15, 15, 300, 300 ),;
                oCamera:oWnd := oWnd, oCamera:hWnd := hWnd, oCamera:Link(),;
                oScan := TTimer():New( 500, { || ScanQR( oCamera, oScan ) }, oWnd ),;
                oScan:Activate() ) ;
      VALID ( If( oScan != NIL, oScan:DeActivate(), ), .T. )

return nil

static function ScanQR( oCamera, oScan )

   static lBusy := .F.
   local cTmp := hb_DirTemp() + "qrscan.bmp"
   local hRes

   if lBusy
      return nil
   endif

   lBusy := .T.
   FErase( cTmp )

   if oCamera:SaveToBmp( cTmp )
      hRes := QRReadFile( cTmp )
      if hRes != NIL
         oScan:DeActivate()               // stop at the first QR found
         MsgInfo( hRes[ "text" ], "QR found" )
      endif
   endif

   lBusy := .F.

return nil

Keep your TakePhoto() and the PRG part with DSHOWCAMERA as they are, and build the program together with qrread.prg (samples\misc\qrread.prg). The video window is only 300 x 300 pixels, so hold the QR big and well lit in front of the camera. You can make it larger in the SetWindowPos() line.

About the guide frame: here the video is a separate child window drawn by DirectShow, so a frame painted from the main window would be hidden behind it. The example above only scans. A frame on top of the video needs another approach (for example the TMfWebCam class of the current build, where the preview is a normal IMAGE control). The frame that follows the QR still needs the corners of the code, as I explained.

I have not compiled this nor tested it with a real camera. I checked that TWindow has the method SaveToBmp( cFile ) that returns .T. or .F., and that TTimer has New(), Activate() and DeActivate(). I could not check that SaveToBmp() captures the DirectShow video in your PC, but your own TakePhoto() uses the same call. Please tell us what you get.

Dear Jimmy,

Good, this is the current dshow.prg, with oDlg, oLive and TMfWebCam, so my example from post #286591 fits this one.

About the two warnings (C4996, wcstombs and fopen): they are only Microsoft "this function may be unsafe" notices from the C part of the sample. The program is built successfully, so you can ignore them.

About the image you attached: I could read it. The message "Media Foundation could not open the camera. Close browser/Teams if they use it." comes from oCam:Connect() in dshow.prg, when MfCamOpen() returns 0, that is, Media Foundation could not open the camera. These are the usual reasons to check:

  • Another program is using the camera at that moment (browser, Teams, Zoom, the Windows Camera app, or another copy of your own test program from before). Close all of them and start the sample again.

  • The Windows camera privacy setting does not allow desktop apps to use the camera (Settings, Privacy, Camera, "Let desktop apps access your camera").

  • The PC has no camera that Media Foundation can see, or it is disabled in Device Manager.

After you press OK the window still opens, but without video, because Connect() failed. You can also press the "Connect" button of the sample after closing the other program, without restarting it.

Dear Jimmy,

I cannot test your build here, so please take this as the most likely cause I can see in your log, not as a sure answer.

About HB_CMDLINE(): it is not in your code. The message "Referenced, missing, but unknown function(s): HB_CMDLINE()" appears because hbvmmt.lib (cmdarg.obj) references it. It is only a consequence of the link failing, so you can ignore it.

The real errors are the ones that say "imp_floor", "imp_srand", "imp_rand", "imp_modf", "imp_fgetc", "impbeginthreadex" and similar. These are all functions of the Microsoft C runtime, and the "imp_" prefix means that the Harbour libraries expect to import them from the dynamic runtime. In your HBP you have this line:

Code: Select all Collapse
-ldflag=/NODEFAULTLIB:msvcrt

That line tells the linker to leave out exactly that runtime, so those functions are left unresolved. As far as I know, that option is not needed when you build with MSVC.

Things to try, one at a time, in your DSHOW.HBP:

  • Remove the line -ldflag=/NODEFAULTLIB:msvcrt.

  • Remove -LC:\BCC7764\lib\psdk: it is a Borland (BCC) path. With MSVC the Windows SDK already gives you uxtheme.lib, so -lUxtheme alone should be enough.

  • The log shows hbvmmt.lib, that is the multithread Harbour VM, because of -mt. The FWH script samples\buildh64.bat for MSVC 64 bit links the normal hbvm.lib, without -mt, and without xhb.hbc. If you do not need threads in this test, remove -mt and also xhb.hbc, hbfoxpro.hbc, hbodbc.hbc and hbmzip.hbc to keep the project small. For a QR test you need FiveH64, FiveHC64, hbwin and the Harbour base libraries.

The LNK4217/LNK4286 warnings about libucrt.lib are only warnings, they come from mixing runtimes and should go away when the above is fixed.

If it still fails after this, please paste only the lines with "error", not the warnings, and tell us which Harbour you use (the folder c:\harbour64 and how it was built, with MSVC 64 bit). I also have not tested your HBP with a real camera or with this exact Harbour build.

Dear Jimmy,

Good, so the build works with your BUILD64.BAT. The C4996 warnings (wcstombs, fopen) are only deprecation notices from Visual C++, they are harmless.

1) Front camera
Today there is no public API to choose the camera. Connect() takes no parameters, and the choice is made inside the embedded C code (MfPickDevice()): it lists the devices, discards some unwanted names and prefers names containing "FaceTime", "Camera" or "Webcam" (FaceTime wins). After opening, cDevice only tells you which one was used. Source() adjusts things like brightness and zoom, not the camera. So at the moment you cannot select the front camera without changing that embedded C code. A way to list and select cameras could be a future improvement, but I can not promise it.

2) "Take a Photo" without a QR code
This is normal. It saves the photo and shows it in the small window. If there is a QR code in the image, the reader will decode it.

3) The two BMP files

  • dshowphoto.bmp is written by "Take a Photo" and overwritten each time.
  • dshow_frame.bmp is the frame saved by the timer (about every 66 ms), loaded into the window and copied to the clipboard.
    Both use a relative path, so they are created in the current working directory. They are not deleted when you quit: Disconnect() only closes the camera and the timer. You can delete them yourself without any problem, or point oCam:cFrameFile to a temporary folder.

Dear Jimmy,

I am glad it works now. Your idea is right: moving the timer to the button will work. I have not tested it here, so please try it.

There is one detail. If the user presses the button several times, your version creates a new timer each time, and the old ones keep running. The cleaner way is to create the timer once at the start, without activating it, and start it only in the button action.

At the start of the program (replace your current line):

Code: Select all Collapse
oScan := TTimer():New( 400, {|| ScanQR( oCam, oScan ) }, oDlg )
// do not call oScan:Activate() here

In the "Take Photo" button:

Code: Select all Collapse
ACTION ( oCam:Save( NIL, ".\dshowphoto.jpg", 90 ), ;
         oSnap:LoadImage( , ".\dshowphoto.jpg" ), oSnap:Refresh(), ;
         oScan:DeActivate(), oScan:Activate() )

The DeActivate() before Activate() makes sure the timer starts clean if it was already running. This way there is only one timer, no matter how many times the button is pressed.

Remember that the QR code must be in front of the camera when you press the button, because the timer reads the frames that the camera gives after that moment.
