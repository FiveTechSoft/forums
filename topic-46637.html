July 2026

  • Enhancement: Class TWebView2 Method New() accepts a third optional
    parameter cBrowserExecutableFolder (Microsoft's browserExecutableFolder).
    When set, WebView2 loads the Fixed Version / standalone Runtime from that
    folder instead of the Evergreen Runtime installed on the system. Useful on
    older OS (e.g. Windows Server 2012 R2) where current Evergreen builds no
    longer work, or when the Runtime cannot be installed machine-wide.
    Example:
    oWeb := TWebView2():New( oWnd, , "C:\MiPrograma\WebView2Runtime" )
    The path must be the Fixed Version root (folder that contains
    msedgewebview2.exe). Existing code without the parameter is unchanged.
    Also fixed: cUserDataFolder (2nd parameter) was being overwritten with a
    default AppData path; it is now honoured.

  • Fix: MAPISendMail() / DEFINE MAIL ÔÇö when TO is given with a single
    parameter (TO cEmail), only MapiRecipDesc.lpszName was filled and
    lpszAddress stayed empty. Outlook often accepts that; Thunderbird and
    other stricter Simple MAPI clients leave the To: field empty.
    mapi.c now copies the display name into the address when the address
    is empty (same effect as TO cEmail, cEmail). Dual form
    TO cName, cAddress is unchanged. Origin and MAPIAddress() predefined
    recipients use the same fallback.
    https://forums.fivetechsupport.com/ (thanks for the detailed report)

    https://forums.fivetechsupport.com/viewtopic.php?p=285833#p285833
    Thanks to Adolfo.

  • Fix: TXBrowse: SelectRow() on a browse using SetMultiSelectCol() raised
    a "Zero divisor" error when the browse had no SetSum() / totaled columns.
    Now SelectRow() only saves/recalcs totals when ::aSumCols is not empty,
    ReCalcTotals() returns immediately when there are no totaled columns, and
    TXBrwColumn:footerStr() guards the standard-deviation division (nCount-1
    could be zero with a single counted row). Ctrl+click, Shift+click, double
    click and header select-all/clear work and keep aSelected consistent with
    no changes required in user code.

  • New: Tensor Logic engine ÔÇö Pedro Domingos' "Tensor Logic: The Language of
    AI" (arXiv:2510.12269) implemented in FWH. A program is a set of tensor
    equations; logical rules and Einstein summation are the same operation, so
    one engine runs both neural components and symbolic (Datalog) reasoning:

  • source\function\fwtensor.c: FWT_EinSum( cSpec, t1, ... ) generalized
    Einstein summation over FW_Tensor float32 tensors (join + projection,
    the paper's single construct), new nonlinearities FWT_SoftmaxLast,
    FWT_Sigmoid( t, nTemperature ), FWT_Step, FWT_ReLU, FWT_Tanh,
    FWT_LNormLast, their backward kernels (FWT_ActDeriv,
    FWT_SoftmaxBackwardLast, FWT_LNormBackwardLast), utility ops
    (FWT_Mul, FWT_Sub, FWT_Fill, FWT_Clone, FWT_MaxDiff) and C-speed tensor
    builders replacing per-element PRG loops (FWT_OneHot, FWT_CausalMask,
    FWT_SinPos, FWT_NotEq, FWT_UnitEmb).
  • OpenBLAS acceleration: fwtensor.c loads OpenBLAS DYNAMICALLY at first
    use (libopenblas.dll on PATH / beside the exe, or the FWT_BLAS_DLL env
    var; set it to "off" to force the portable C loops; ILP64 builds such as
    numpy's libscipy_openblas64_ are detected too). Never a hard dependency.
    FWT_MatMul and every 2-operand FWT_EinSum reducible to a (batched) GEMM
    run on cblas_sgemm, using BLAS transposes so the common attention
    patterns need no repacking. FWT_BlasActive() reports the backend.
    Measured on a Xeon W-2140B (8c): 1024x1024x1024 matmul went from
    0.32 GFLOPS (C loops) to 497 GFLOPS ÔÇö above numpy's OpenBLAS (446) and
    within 2x of PyTorch/MKL (982) on the same machine.
  • source\classes\tensorlogic.prg: TTensorLogic ÔÇö tensor logic programs as
    equation strings: oTL:Eq( "Y = step( W[i,j] * X[j] + B )" ).
    Joins, projections, nonlinearities (step, sigmoid, relu, tanh, gelu,
    softmax, lnorm), Run() = forward chaining to fixpoint (recursive Datalog
    rules converge), and automatic differentiation: the gradient of an
    equation is the same einsum with factor and output swapped, so
    Forward() / Seed() / Backward() / Step() train ANY program with no
    hand-written backprop (verified against central finite differences,
    max error 1e-6). Datalog over DBF tables: TTLDomain maps entity names
    to tensor indices, LetDbf() turns records into boolean relation tensors,
    LetSet() unary predicates, Query() decodes result tensors back to tuples
    of names. Helpers TL_TensorND(), TL_NotEq(), TL_UnitEmb().
    Terms with ANY number of factors are evaluated by chaining pairwise
    contractions (only the letters still needed survive each step), so every
    step takes the BLAS GEMM fast path. TTransformerTL (GPT-style
    transformer facade over a tensor logic program: New / ForwardSeq /
    TrainStep / AccumStep / EvalLoss / Generate / LoadFromTransformer) also
    lives in tensorlogic.prg.
    Professional training support: StepAdam() (Adam optimizer, C kernel
    FWT_AdamUpdate with bias correction), ClipGrads() (global L2 gradient
    clipping, C FWT_SumSq/FWT_ScaleInPlace), gradient ACCUMULATION across
    mini-batches (AccumStep + ClearActGrads: parameter grads add up,
    activation grads reset), and checkpointing: SaveParams()/LoadParams()
    persist every Param() tensor as raw float32 (C FWT_GetBytes/FWT_SetBytes)
    plus a user hash (vocabulary, config).

    behind DeepSeek's small KV cache), RoPE (rotary positions as a

    top-k + temperature sampling and tokens/s metrics. Everything

  • New: samples\ai\tlc.prg ÔÇö the synthetic-training recipe for code,
    end to end in miniature ("how would a model learn C without a human
    dataset"). A mini-C toy language (2 variables, mod-10 arithmetic, if):
    1) synthetic GENERATOR of valid programs with a built-in exact ORACLE
    (the pair every code-training pipeline needs, at zero labeling cost);
    2) EXECUTION LEARNING: a TL transformer predicts the output of programs
    it has never seen ÔÇö 36-40% exact-digit accuracy vs 10% chance ÔÇö with
    the key finding documented in code: a single answer target per
    sequence learns nothing (chance); dense next-char targets plus the
    answer (multitask) is what makes the task land;
    3) GRAMMAR-CONSTRAINED DECODING: a prefix automaton masks illegal
    characters during sampling ÔÇö an UNTRAINED model emits 25/25 valid
    programs (free sampling: 0/25). Syntax is imposed, never learned.
    Also documents a Harbour numeric gotcha: LCG multipliers like 1103515245
    overflow double precision (n*mult > 253) and the random stream silently
    degenerates ÔÇö use MINSTD (48271) with Int().

  • Fix: FWMariaConnection bOnLostServer not fired on AUTOMATIC reconnect
    (source\internal\fwmaria.prg):
    The client option MYSQL_OPT_RECONNECT was enabled on connect, so when the
    server dropped the connection (wait_timeout, network oscillation, KILL) the
    MySQL/MariaDB client library silently re-opened the session INSIDE
    mysql_real_query() and retried the statement itself: no error, no callback,
    and all SET SESSION state (time_zone, sql_mode, lc_time_names, ...) silently
    reverted to server defaults, so applications kept writing data with wrong
    session settings. Only the explicit oCn:ReConnect() path fired bOnLostServer.
    Fixed: driver-level auto-reconnect is now DISABLED; a dead session always
    surfaces as an error, and only the controlled helper mysql_ping_reconnect()
    in C may revive it (it detects the reconnect via mysql_thread_id() change and
    flags it to the PRG layer). Execute_Sql()/Check() then fire bOnLostServer,
    re-apply tracked session state (RestoreSessionState()) and retry the failed
    statement, both on the explicit ReConnect() path and on the automatic path
    (plain Execute on a dropped connection). No statement runs any longer on a
    reconnected session before its state is restored.
    Unit test: samples\fwmaria_ut.prg (U_TestAutoReconnect). Sample: fwmatz.prg.

  • Fix: samples\fwmalost.prg could be mistaken for a library error dialog:
    FWSetLanguage( 1 ) selects English, not Portuguese (4 = Portuguese), and the
    demo MARIA_ONCONNECTERROR hook itself showed a MsgStop() built with the same
    FWString() texts the library uses ("Error" title, "Please check your
    connection and try again"), so the sample's own dialog looked like a
    non-suppressible library MessageBox. To be clear: the library shows NO dialog
    on a failed connect while lShowErrors / lShowMessages keep their default .F.
    The sample now selects Portuguese and titles its own dialog
    "APP HOOK: MARIA_ONCONNECTERROR".

  • Fix: TWBrowse array-bound error (BASE/1132) on drag-scroll and inertial
    (flick) scroll near the end of the data (source\classes\wbrowse.prg):
    LButtonUp() and MouseMove() advanced ::nAt directly by the visible row count
    ( ::nRowCount() - ::nRowPos ) without the [1, nLen] clamp that ::bSkip
    already enforces. When fewer records remained than visible rows (array
    length not a multiple of the pane height), ::nAt overshot ::nLen and the
    next bLine evaluation indexed past the end of the array. Now the three
    direct ::nAt writes apply the same clamp used in SetArray()'s bSkip:
    ::nAt := Min( Max( ::nAt, 1 ), Eval( ::bLogicLen, Self ) ), which also
    refreshes ::nLen.

  • Fix: FW_SaveImage() silent crash saving alpha bitmaps to JPG/PNG/GIF/TIFF
    (source\winapi\gdipfwh.cpp):
    A March 2025 memory-leak fix in GDIP_SAVEIMAGE() added a second delete of the
    GDI+ bitmap after BitmapFromAlphaBmp(), which already frees the original image
    internally. Saving 32-bit alpha HBITMAPs (e.g. after GdiBmp:Conver24to32Alpha()
    or bmp2alpha()) to non-BMP formats caused a double-free and immediate process exit
    with no Harbour error. Restored the pre-leak-fix assignment pattern:
    pImage = BitmapFromAlphaBmp( pImage ). Affected typical barcode/QR workflows such as
    FW_BarCodeBmp() + bmp2alpha() + FW_SaveImage( hBmp, cFile + '.jpg' ).

  • Fix: MsgYesNoCancel() returned logical instead of Windows button code
    (source\function\msgs.c):
    Since the 2015 Unicode refactor, MSGYESNOCANCEL used hb_retl() on the raw
    MessageBox return code, so every choice (Yes/No/Cancel) evaluated as .T.
    Restored hb_retnl() so the function again returns 6 (Yes), 7 (No), 2 (Cancel).

  • Fix: TGet:KeyDown bKeyDown reads stale bound variable (source\classes\tget.prg):
    On xHarbour, TGet:KeyDown evaluated bKeyDown before syncing the edit buffer to
    the bound variable. bKeyDown callbacks that read the variable (e.g. Enter key
    handlers for product-code lookups) saw a stale/empty value because the buffer
    was never committed. Fixed: sync oGet:buffer from GetWindowText/GetText, then
    VarPut(UnTransform()) / VarPut(GetText()) before Eval(bKeyDown), mirroring what
    lValid/KeyChar already do. VarPut is used instead of full Assign() to avoid
    resetting oGet:Original and oGet:Changed, which would break bChange in KeyChar
    for VK_RETURN/VK_TAB. Sample: samples\getkdwn.prg.

  • Fix: FWMariaConnection hardcoded English error dialog not suppressible
    (source\internal\fwmaria.prg):
    On connection error, ShowError() called Msg_Alert() unconditionally, showing
    a hardcoded English MessageBox even when lShowErrors was .F. or the app wanted
    to localise errors. Fixed: ShowError() now checks lShowErrors .or. lShowMessages
    before calling Msg_Alert(). Apps can suppress all internal error dialogs by
    setting oCn:lShowErrors := .F. Connect-time errors can be localised via the
    optional MARIA_ONCONNECTERROR( nError, cErrMsg, oCn ) hook or :bOnConnectError.
    The "Please check your connection..." suffix is now passed through FWString().
    Sample: samples\fwmalost.prg.

  • Fix: FWMariaConnection silent reconnect gives app no hook (source\internal\fwmaria.prg):
    When the connection dropped, mysql_ping auto-reconnect retried the next
    statement in C with no callback and no re-apply of SET SESSION state
    (time_zone, lc_time_names, etc.). Fixed: C marks reconnect but does not
    retry the failing query; Check()/ReConnect() fire bOnLostServer and
    RestoreSessionState() re-applies tracked session vars before PRG retries.
    Sample: samples\fwmatz.prg.

  • Fix: FWMariaConnection transaction silently split on auto-reconnect
    (source\internal\fwmaria.prg):
    If the socket died with START TRANSACTION open, mysql_ping auto-reconnect
    retried the next statement on a fresh autocommit session with no error.
    Fixed: client-side lInTransaction tracking, HandleLostTxn() blocks ping-retry
    in C and PRG while a transaction is open, fires bOnLostServer, and surfaces
    error 2013 with a localised message. Sample: samples\fwmatx.prg.

  • New: FWMariaConnection schema metadata cache (source\internal\fwmaria.prg):
    Restored hMetaCache for DbExists, TableExists, FKeyColumns and ListViews (public
    methods delegate to *_org implementations). Positive DbExists/TableExists results
    are cached; FKeyColumns and ListViews cache all results. DDL (CREATE/DROP/ALTER/

    short-circuits when ::cDB is already set; SelectDB() forces a re-read. Unit tests:

    FWMARIA_WAS_RECONNECTED() could return NIL under xHarbour, crashing Execute_Sql at the

  • New sample: testrsz.prg - how to resize an XBrowse at runtime without
    flickering. A plain oBrw:nHeight := nNew assignment repaints twice
    (MoveWindow() immediate repaint plus the later Refresh()) and the dialog
    background erase paints over the browse area before the rows are redrawn,
    both visible as flicker. The correct method: add WS_CLIPCHILDREN to the
    dialog style (FiveWin dialogs do not set it by default), freeze the dialog
    with WM_SETREDRAW around the resize, then repaint dialog + browse once
    (TWindow:Refresh() is a plain InvalidateRect() and does not cascade to
    children, so both Refresh() calls are needed). The sample includes "old
    method" buttons side by side for comparison. Also documented in the
    TXBrowse HTML docs (Example 5: Flicker-Free Runtime Resize).
