Hi FWExplorer,

Thanks for checking the Borland artifact again and for the details. The SHA-256 you reported for the ZIP matches the digest GitHub lists for that CI artifact. That confirms we are discussing the same published ZIP, but it does not yet tell us why harbour.exe shows no output, or what triggered Malwarebytes.

For anyone checking a SHA-256 on Windows: open Command Prompt in the folder containing the downloaded file and run:

Code: Select all Collapse
certutil -hashfile harbour_win32_bcc_20260829.zip SHA256

For this ZIP, compare the 64-character hash in the result with GitHub's artifact digest (omit its sha256: prefix):

Code: Select all Collapse
86c85dc5f01171497ff9576a74d5afe30a1f61c7ce4a24e422dd7ac7a85dd4b2

To hash the extracted executable, go to its bin folder and run:

Code: Select all Collapse
certutil -hashfile harbour.exe SHA256

Alternatively, in PowerShell, use Get-FileHash .\harbour.exe -Algorithm SHA256 and read the Hash column. The file path must point to the file you actually tested; hashing the ZIP and hashing the EXE give different values.
