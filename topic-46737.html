Estimado Jorge,

Si los platos son botones u otros controles creados OF oPanel, hay que terminar esos controles antes de crear los de la nueva categoría. No basta con asignar un array vacío a oPanel:aControls, porque eso solo elimina las referencias, no las ventanas de los controles.

He revisado el fuente actual: TScrollPanel no define un método Clear(). Sus controles se registran en aControls y el método End() de TControl los retira de ese array. Por eso conviene recorrer una copia, en orden inverso, y no un AEval() sobre el mismo array que End() está modificando.

El esquema para cambiar una categoría por otra es:

Code: Select all Collapse
// Antes de eliminar los controles, volver al origen
if ! Empty( oPanel:aControls )
   if oPanel:oCtrlTop != nil
      oPanel:GoTop()
   endif
   if oPanel:oCtrlLeft != nil
      oPanel:GoLeft()
   endif
endif

// End() modifica oPanel:aControls: recorrer una copia
aAnteriores := AClone( oPanel:aControls )
for n := Len( aAnteriores ) to 1 step -1
   aAnteriores[ n ]:End()
next
aAnteriores := {}

// Solo si utilizas AddText() o SetPage()
oPanel:aSays  := {}
oPanel:aPages := {}

// AQUI creas los controles de la nueva categoria OF oPanel
// ...

// Recalcular DESPUES de crear los nuevos controles
if ! Empty( oPanel:aControls )
   oPanel:SetRange()
endif
oPanel:Refresh()

Declara aAnteriores y n como LOCAL al comienzo de tu función. El ejemplo supone controles normales derivados de TControl y que vuelves a cargar una categoría con controles. No es una función Clear() general: en el fuente actual SetRange() no reinicia el estado cuando aControls está vacío, y las referencias internas a los controles extremos deben renovarse al cargar los nuevos.

Además, End() solicita el cierre mediante un mensaje de Windows; no significa que todas las ventanas hayan terminado de destruirse en esa misma línea. Evita seguir utilizando los objetos de la categoría anterior.

Este esquema está contrastado con el fuente, pero no lo he compilado ni ejecutado. Si nos muestras cómo creas los botones/platos y la versión de FWH que utilizas, podemos ajustarlo a tu código, especialmente si hay categorías vacías o controles propios.

Estimado Jorge,

El problema está en BorroControl(): el método End() de un control ya se quita a sí mismo del array oPanel:aControls (lo busca por hWnd, hace ADel y reduce el tamaño del array). Por eso, al llamar después a HB_ADel( oPanel:aControls, nItem, .t. ), estás borrando del array otro control, el que ocupaba el siguiente lugar, sin destruir su ventana. Ese botón sigue visible pero el panel ya no lo conoce y no recibe bien el ratón ni el foco. Como siempre borras el item 1, el afectado es el primer botón de la nueva carga.

Solución: quita la línea HB_ADel y no hace falta mover nTop/nLeft antes de borrar (el panel se reordena al crear los nuevos botones). Para vaciar el panel basta esto:

Code: Select all Collapse
function VaciarPanel( oPanel )

   do while Len( oPanel:aControls ) > 0
      ATail( oPanel:aControls ):End()
   enddo

   oPanel:SetRange()
   oPanel:Refresh()

return nil

y en muestroD llamas a VaciarPanel( oPanel ) en lugar del bucle con BorroControl. Nota: el código de arriba es un ejemplo mío sin probar; el punto sobre End() y aControls sí está comprobado en el código de la clase.

Un detalle más: en tu bucle de creación, la condición do while ! eof() .or. depto <> wdepto probablemente quieras que sea ! eof() .and. depto == wdepto; con el .or. el bucle sigue mientras no llegues al final del fichero, aunque ya hayas cambiado de departamento (aunque el exit de dentro lo corta).

Si después de este cambio sigue fallando, publica el código completo de la creación de oPanel y de un botón.

Tienes razón y te pido disculpas: mi respuesta anterior estaba equivocada para tus botones. Revisé la clase del botón: BTNBMP tiene su propio End() que solo destruye la ventana y no se quita de oPanel:aControls. Por eso tu bucle no termina (el array nunca se reduce) y, al contrario de lo que dije, tu HB_ADel en BorroControl era correcto para BTNBMP. Solo los controles que usan el End() genérico de TControl se quitan solos del array.

Para vaciar el panel sin depender de eso, prueba esto (ejemplo mío sin probar):

Code: Select all Collapse
function VaciarPanel( oPanel )

   local oCtrl

   for each oCtrl in AClone( oPanel:aControls )
      oCtrl:End()
   next

   oPanel:aControls := {}
   oPanel:SetRange()
   oPanel:Refresh()

return nil

Recorre una copia del array, destruye cada control y luego deja el array vacío, valga el tipo de control que sea.
