Armando, hay un dato importante en ese número: -2147023170 corresponde a 0x800706BE, cuyo código Windows es RPC_S_CALL_FAILED, «la llamada a procedimiento remoto falló». Aunque el mensaje de WINOLE diga «Argument error: ADD», eso no demuestra que falte un argumento: Microsoft documenta Workbooks.Add con Template opcional.

Tampoco significa necesariamente un fallo de la LAN: la llamada de automatización a Excel puede fallar en el propio equipo. Que Excel esté instalado no garantiza que pueda crear un libro en la cuenta y sesión desde las que ejecutas el programa.

Primero separaría estos casos:

  • En el servidor, con la misma cuenta de Windows que ejecuta tu aplicación, ¿Excel abre manualmente y permite crear y guardar un libro nuevo? Comprueba si aparece algún aviso pendiente; no hace falta cambiar permisos para esta prueba.
  • ¿El EXE se ejecuta allí en una sesión de usuario abierta, o desde un servicio/tarea programada sin sesión interactiva? La advertencia de Microsoft sobre automatización desatendida de Office se refiere a ese contexto, no simplemente a que el equipo se llame «servidor».
  • Indica Windows, versión de Excel, FWH y Harbour/xHarbour del equipo que falla, y si al producirse el error Excel se cierra o queda algún aviso visible. Si el Visor de eventos registra un fallo de EXCEL.EXE en ese instante, bastan el código y módulo del fallo, sin nombres de documentos ni datos privados.

Con eso podremos distinguir un problema de inicio/perfil/contexto de ejecución de un fallo posterior de Excel. No daría todavía como solución reinstalar Office, ejecutar como administrador, abrir puertos ni modificar DCOM. No he reproducido tu equipo y el código de error por sí solo no fija la causa.

FUNCTION Armando_Excel()

   LOCAL oExcel, oBook, oSheet, nVez

   // Tenta criar a aplicação Excel
   oExcel := CREATEOBJECT( "Excel.Application" )

   IF Empty( oExcel )
      MsgStop( "O Microsoft Excel não está instalado ou não pôde ser iniciado.", "Erro" )
      RETURN
   ENDIF

   // Oculta o Excel durante a manipulação para evitar piscadas na tela
   oExcel:Visible := .F. 

   // Protege a criação do Workbook
   TRY
      oBook := oExcel:WorkBooks:Add()
   CATCH
      MsgStop( "Erro ao criar a nova planilha (Workbook).", "Erro OLE" )
      oExcel:Quit()
      RETURN
   END

   // Remove as abas excedentes mantendo apenas uma
   FOR nVez := oBook:Sheets:Count() TO 2 STEP -1
      oBook:WorkSheets(nVez):Delete()
   NEXT

   oSheet := oExcel:Get("ActiveSheet")
   

   // Torna visível após configurar se desejar
   oExcel:Visible := .T.

RETURN NIL

Armando, si no funciona, revisa tu Excel. Aquí funcionó a la perfección.

Code: Select all Collapse
//-> C:\FWH2603\SAMPLES\ARMANDO5.PRG

#include "FiveWin.ch"

FUNCTION Main()

   Armando_Excel()

RETURN NIL

FUNCTION Armando_Excel()

   LOCAL oExcel := NIL, oBook := NIL, oSheet := NIL
   LOCAL oErr, cMsg := "", lOk := .F.

   TRY

  oExcel := CREATEOBJECT( "Excel.Application" )

  IF ValType( oExcel ) == "O"

     oBook  := oExcel:WorkBooks:Add( -4167 )

     oSheet := oExcel:Get( "ActiveSheet" )

     oSheet:Range( "A1" ):Value := "Produto"
     oSheet:Range( "B1" ):Value := "Quantidade"
     oSheet:Range( "A2" ):Value := "Racao"
     oSheet:Range( "B2" ):Value := 10
     oSheet:Range( "A3" ):Value := "Shampoo"
     oSheet:Range( "B3" ):Value := 5

     oExcel:Visible := .T.

     lOk := .T.

  ELSE

     cMsg := "Excel.Application nao foi criado."

  ENDIF

   CATCH oErr

  cMsg := "Erro ao criar a planilha no Excel:" + Chr(13) + Chr(10) + ;
          cValToChar( oErr:Description ) + Chr(13) + Chr(10) + ;
          "Operacao: " + cValToChar( oErr:Operation )

   END

   IF ! lOk
      MsgStop( cMsg, "Erro OLE" )
   ENDIF

RETURN NIL
