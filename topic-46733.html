Dear wartiaga,

Thank you for the full error log. I have not been able to compile or run your project, so these are the most common causes I would check first. They are not confirmed for your PC.

What the error means
"Cannot create Dialog Box" with a resource name means that Windows found (or did not find) the resource MOSTRATAB but could not build the dialog window from it. Your log shows the call comes from TDIALOG:ACTIVATE, so the dialog object was created but the Windows dialog could not be.

Things to check

  • Is the resource in the EXE that is running? An old .res (or one for another EXE) can be linked, or the .res was rebuilt but the EXE was not relinked. Rebuild everything and make sure the running transp32.exe is the new one, not an old copy in another folder.

  • A control class that is not registered. This is the most frequent reason when the ID and the name are correct. If MOSTRATAB uses a custom control, a RichEdit, an ActiveX, SysListView32, SysTreeView32 or any other common control, the DLL or class must be loaded before Activate(). Try opening the dialog after your app has done its usual initialization.

  • Find the guilty control by bisection. In the .rc, remove half of the controls, rebuild and test. Repeat on the half that fails. This usually finds the control that cannot be created in a few steps.

  • Dialog style and size. Check that the dialog is not declared with a style that needs a parent that does not exist yet, and that the size is reasonable for the screen.

  • Resource name. Check that the name in the .rc is exactly MOSTRATAB, with no extra spaces, and that it is a DIALOG (not a different resource type with the same name).

To help you further, please post:

  • your FiveWin version (FWH build) and your xHarbour and C compiler,

  • the line that creates the dialog (the DEFINE DIALOG ... RESOURCE "MOSTRATAB" line),

  • the MOSTRATAB block from your .rc file.

I see in your window list that you already made test projects for MOSTRATAB. If the minimal test works and the full program fails, the difference is usually in the initialization or in the libraries linked, so comparing both would be the next step.
