Archivo temporal: crear, escribir, releer y borrar con control de errores

Posted: Thu Nov 19, 2026 10:56 AM

Ciclo de vida completo de un archivo temporal con GetTempPath y GetTempFileName

Hola a todos:

Seguimos con la serie de ejemplos de programación Windows con FiveWin. En el foro ya hay fragmentos que usan GetTempPath o GetTempFileName por separado para obtener la carpeta temporal o un nombre; hoy juntamos el ciclo completo en un solo ejemplo: obtener la carpeta temporal del sistema, crear ahí un archivo temporal, escribir en él, releerlo y borrarlo, controlando los errores de cada paso y siguiendo la pista del archivo propio hasta el final, con un aviso claro si no se puede borrar.

Lo que dice la documentación de Microsoft

  • GetTempPath devuelve la carpeta temporal mirando, en este orden, las variables de entorno TMP, TEMP y USERPROFILE, y por último el directorio de Windows. La ruta devuelta termina en barra y la función NO comprueba que exista ni que tengamos acceso: hay que verificarlo antes de usarla.
  • GetTempFileName con uUnique = 0 no solo inventa un nombre: CREA el archivo vacío y lo cierra. Del prefijo que le pasemos usa solo los tres primeros caracteres (del juego de caracteres OEM) y con el mismo prefijo y carpeta solo puede dar 65.535 nombres distintos.
  • Con uUnique distinto de 0 solo genera el nombre, sin crear el archivo ni garantizar que sea único.
  • Los temporales creados por GetTempFileName NO se borran solos: hay que borrarlos (la documentación sugiere DeleteFile; aquí usamos las funciones de archivo de Harbour, que es lo habitual en una aplicación FiveWin).
  • La documentación indica que las aplicaciones deberían llamar a GetTempPath2 en lugar de GetTempPath; este ejemplo usa la clásica GetTempPath. El mínimo documentado de estas dos APIs es Windows XP. Ambas viven en kernel32: usarlas no añade ninguna biblioteca a la aplicación.

El ejemplo completo

Una ventana con un botón Ejecutar ciclo que hace las cuatro fases y muestra el resultado real de cada una: carpeta temporal, archivo creado, bytes escritos, contenido releído y borrado. La escritura, relectura y borrado van con funciones Harbour (FCreate/FWrite/FClose, MemoRead, FErase) y las dos APIs de Windows solo para la carpeta y el nombre. Lo interesante es el comportamiento ante errores:

  • Cada fila muestra su resultado real; si algo falla, el estado lo dice y el detalle queda en su fila, nada de "ciclo completo" automático.
  • Al reintentar se limpian las filas: no quedan valores de la ejecución anterior.
  • Si un temporal no se puede borrar, el programa recuerda su ruta y reintenta al pulsar de nuevo o al cerrar; mientras siga pendiente NO crea otro, para no perder la pista del que quedó.
  • Al cerrar la ventana se hace el mismo intento de limpieza y, si no se puede borrar, un aviso muestra la ruta exacta del temporal que queda. No hay limpieza garantizada: se informa y se deja salir. Y el programa solo borra archivos que él mismo ha creado, nunca ajenos.

//----------------------------------------------------------------------------//
// TEMPCYCLE.PRG (v4)
// Ciclo de vida completo de un archivo temporal:
// GetTempPath + GetTempFileName, escribir, releer y borrar
// Ejemplo didactico FiveWin (FWH) + Harbour
//
// Que muestra:
//   - GetTempPath devuelve la carpeta temporal del sistema mirando,
//     en este orden, TMP, TEMP, USERPROFILE y por ultimo el
//     directorio de Windows; la ruta termina en barra y la funcion
//     NO comprueba que exista ni que tengamos acceso (doc. Microsoft)
//   - GetTempFileName con uUnique = 0 no solo inventa el nombre:
//     CREA el archivo vacio y lo cierra; usa los 3 primeros
//     caracteres del prefijo (juego de caracteres OEM) y solo llega
//     a 65535 nombres distintos para el mismo prefijo y carpeta
//     (doc. Microsoft)
//   - Con uUnique distinto de 0 solo genera el nombre, sin crear el
//     archivo ni garantizar que sea unico (doc. Microsoft)
//   - Los temporales NO se borran solos: hay que borrarlos
//     (doc. Microsoft); aqui el programa solo borra archivos que el
//     mismo ha creado
//
// La escritura, relectura y borrado se hacen con funciones Harbour
// (FCreate/FWrite/FClose, MemoRead, FErase), que es lo habitual en
// una aplicacion FiveWin; las dos APIs de Windows se usan para la
// carpeta y el nombre.
//
// Este programa usa las variantes ANSI de las APIs (GetTempPathA /
// GetTempFileNameA), coherentes con una aplicacion Harbour ANSI.
//
// Minimo documentado de estas dos APIs: Windows XP (doc. Microsoft
// de GetTempPath y GetTempFileName). Ambas viven en kernel32: usarlas
// no anade ninguna biblioteca a la aplicacion.
//
// Comportamiento ante errores:
//   - Cada fila muestra su resultado real; si algo falla, el estado
//     lo dice y el detalle queda en la fila correspondiente
//   - Al reintentar se limpian las filas: nada de valores de la
//     ejecucion anterior
//   - Si un temporal no se puede borrar, el programa recuerda su
//     ruta y reintenta el borrado al pulsar de nuevo o al cerrar;
//     mientras siga pendiente NO crea otro, para no perder su ruta
//   - Al cerrar la ventana se hace el mismo intento de limpieza y,
//     si no se puede borrar, un aviso muestra la ruta del temporal
//     que queda antes de salir. No hay limpieza garantizada: se
//     informa y se deja salir
//
// Documentacion de Microsoft:
//   https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-gettemppatha
//   https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-gettempfilenamea
//----------------------------------------------------------------------------//

#include "FiveWin.ch"
#include "fileio.ch"   // F_ERROR y demas constantes de funciones de archivo

static oSayDir, oSayFile, oSayBytes, oSayContenido, oSayBorrado
static oSayEstado

// Ruta del temporal creado por ESTE programa que aun no se ha podido
// borrar; cadena vacia si no queda ninguno pendiente
static cPendiente := ""

// .T. cuando ya se hizo el intento de limpieza+aviso de la salida
static lSalidaAvisada := .f.

#define CONTENIDO_DEMO "Prueba de ciclo de vida de un temporal (FWH)"

//----------------------------------------------------------------------------//

// Ventana con salida segura: el cierre de la ventana y el boton
// Cerrar comparten la misma limpieza con aviso
CLASS TTempCycleWnd FROM TWindow

   METHOD Close()

ENDCLASS

METHOD Close() CLASS TTempCycleWnd

   AvisoYLimpieza()

return nil

//----------------------------------------------------------------------------//

function Main()

   local oWnd

   // Misma construccion que DEFINE WINDOW ... PIXEL, pero de la
   // clase con salida segura definida arriba
   oWnd := TTempCycleWnd():New( 0, 0, 350, 520, ;
      "Ciclo de vida de un archivo temporal", , , , , , , , , , , , ;
      .t., .t., .t., .t., .t. )

   @ 15, 15 SAY "GetTempPath da la carpeta temporal y GetTempFileName crea ahi" OF oWnd SIZE 490, 15 PIXEL

   @ 33, 15 SAY "un archivo vacio de nombre unico. El ejemplo escribe, relee y" OF oWnd SIZE 490, 15 PIXEL

   @ 51, 15 SAY "borra SOLO el archivo que el mismo crea." OF oWnd SIZE 490, 15 PIXEL

   @ 84, 195 BUTTON "Ejecutar ciclo" OF oWnd ;
      SIZE 130, 26 PIXEL ACTION BtnCiclo()

   @ 124, 15 SAY "Carpeta temporal:" OF oWnd SIZE 170, 18 PIXEL
   @ 124, 190 SAY oSayDir PROMPT "" OF oWnd SIZE 315, 18 PIXEL

   @ 146, 15 SAY "Archivo creado:" OF oWnd SIZE 170, 18 PIXEL
   @ 146, 190 SAY oSayFile PROMPT "" OF oWnd SIZE 315, 18 PIXEL

   @ 168, 15 SAY "Bytes escritos:" OF oWnd SIZE 170, 18 PIXEL
   @ 168, 190 SAY oSayBytes PROMPT "" OF oWnd SIZE 315, 18 PIXEL

   @ 190, 15 SAY "Contenido releido:" OF oWnd SIZE 170, 18 PIXEL
   @ 190, 190 SAY oSayContenido PROMPT "" OF oWnd SIZE 315, 18 PIXEL

   @ 212, 15 SAY "Borrado:" OF oWnd SIZE 170, 18 PIXEL
   @ 212, 190 SAY oSayBorrado PROMPT "" OF oWnd SIZE 315, 18 PIXEL

   @ 246, 15 SAY oSayEstado PROMPT "" OF oWnd SIZE 490, 18 PIXEL

   @ 276, 210 BUTTON "Cerrar" OF oWnd ;
      SIZE 100, 26 PIXEL ACTION ( AvisoYLimpieza(), oWnd:End() )

   ACTIVATE WINDOW oWnd CENTERED

return nil

//----------------------------------------------------------------------------//
// Intenta borrar el temporal pendiente de este programa, si lo hay.
// Devuelve .T. si no queda nada pendiente (borrado o no habia).

static function LimpiarPendiente()

   if ! Empty( cPendiente )
      if FErase( cPendiente ) == 0
         cPendiente := ""
      endif
   endif

return Empty( cPendiente )

//----------------------------------------------------------------------------//

static function BtnCiclo()

   local cDir, cFile
   local hFile, nBytes := 0
   local cLeido := ""
   local lEscritura, lLectura, lBorrado

   // Limpiar resultados de la ejecucion anterior
   oSayDir:SetText( "" )
   oSayFile:SetText( "" )
   oSayBytes:SetText( "" )
   oSayContenido:SetText( "" )
   oSayBorrado:SetText( "" )
   oSayEstado:SetText( "Ejecutando..." )

   // Si quedo un temporal sin borrar de una ejecucion anterior de
   // este programa, reintentar primero su borrado (solo esa ruta).
   // Si sigue sin poder borrarse, NO crear otro: se perderia la
   // unica ruta registrada del pendiente.
   if ! LimpiarPendiente()
      oSayEstado:SetText( "Pendiente: " + cPendiente )
      return nil
   endif

   cDir := TF_TempPath()

   if cDir == NIL
      oSayDir:SetText( "(error " + AllTrim( Str( TF_LastError() ) ) + ")" )
      oSayEstado:SetText( "Fallo al obtener la carpeta temporal" )
      return nil
   endif

   oSayDir:SetText( cDir )

   cFile := TF_TempFileName( cDir, "FWE" )

   if cFile == NIL
      oSayFile:SetText( "(error " + AllTrim( Str( TF_LastError() ) ) + ")" )
      oSayEstado:SetText( "Fallo al crear el archivo temporal" )
      return nil
   endif

   oSayFile:SetText( cFile )

   // Desde aqui hay un temporal creado por este programa: recordarlo
   // hasta que el borrado tenga exito
   cPendiente := cFile

   // Escribir (funciones Harbour)
   lEscritura := .f.
   if ( hFile := FCreate( cFile ) ) != F_ERROR
      nBytes := FWrite( hFile, CONTENIDO_DEMO )
      FClose( hFile )
      lEscritura := ( nBytes == Len( CONTENIDO_DEMO ) )
   endif

   if lEscritura
      oSayBytes:SetText( AllTrim( Str( nBytes ) ) )
   else
      oSayBytes:SetText( "(fallo al escribir)" )
   endif

   // Releer (funcion Harbour) y comprobar que coincide
   lLectura := .f.
   if lEscritura
      cLeido := MemoRead( cFile )
      lLectura := ( cLeido == CONTENIDO_DEMO )
   endif

   if lLectura
      oSayContenido:SetText( cLeido )
   else
      oSayContenido:SetText( "(fallo al releer o no coincide)" )
   endif

   // Borrar SOLO el archivo creado por este programa (funcion Harbour)
   lBorrado := LimpiarPendiente()

   if lBorrado
      oSayBorrado:SetText( "Si, el archivo creado" )
   else
      oSayBorrado:SetText( "No (pendiente: reintento al pulsar o cerrar)" )
   endif

   // Estado final segun el resultado real de cada paso
   if lEscritura .and. lLectura .and. lBorrado
      oSayEstado:SetText( "Ciclo completo sin errores; no quedan temporales del ejemplo" )
   else
      oSayEstado:SetText( "Ciclo con errores: el detalle real esta en cada fila" )
   endif

return nil

//----------------------------------------------------------------------------//

// Intenta borrar el temporal pendiente y, si no puede, avisa con su
// ruta. En una misma salida puede activarse dos veces; la bandera lo
// limita a un solo intento y un solo aviso por ejecucion.
static function AvisoYLimpieza()

   if ! lSalidaAvisada
      lSalidaAvisada := .t.
      if ! LimpiarPendiente()
         MsgStop( "No se pudo borrar el temporal creado por el ejemplo:" + ;
                  CRLF + cPendiente + CRLF + CRLF + ;
                  "Queda en disco; puedes borrarlo a mano.", ;
                  "Ciclo de vida de un archivo temporal" )
      endif
   endif

return nil

//----------------------------------------------------------------------------//

#pragma BEGINDUMP

#include <windows.h>
#include "hbapi.h"

// Ultimo GetLastError() de las TF_*
static DWORD s_dwLastError = 0;

// TF_TempPath() -> cCarpeta o NIL
// La ruta devuelta termina en barra; la funcion no comprueba que
// exista ni que haya acceso (doc. Microsoft).
HB_FUNC( TF_TEMPPATH )
{
   char szBuf[ 520 ];
   DWORD nRes = GetTempPathA( sizeof( szBuf ), szBuf );

   if( nRes == 0 || nRes > sizeof( szBuf ) )
   {
      s_dwLastError = ( nRes == 0 ) ? GetLastError()
                                    : ERROR_INSUFFICIENT_BUFFER;
      hb_ret();   // NIL
      return;
   }

   hb_retc( szBuf );
   s_dwLastError = 0;
}

// TF_TempFileName( cCarpeta, cPrefijo ) -> cRutaCompleta o NIL
// Con uUnique = 0 crea el archivo vacio y lo cierra (doc. Microsoft).
HB_FUNC( TF_TEMPFILENAME )
{
   char szBuf[ MAX_PATH ];
   UINT nRes = GetTempFileNameA( hb_parc( 1 ), hb_parc( 2 ), 0, szBuf );

   if( nRes == 0 )
   {
      s_dwLastError = GetLastError();
      hb_ret();   // NIL
      return;
   }

   hb_retc( szBuf );
   s_dwLastError = 0;
}

// TF_LastError() -> ultimo GetLastError() de las TF_*
HB_FUNC( TF_LASTERROR )
{
   hb_retnl( ( long ) s_dwLastError );
}

#pragma ENDDUMP

//----------------------------------------------------------------------------//

Cómo probarlo

  1. Compilar con FWH + Harbour. Estas dos APIs están en kernel32, así que no hay que enlazar ninguna biblioteca adicional por ellas (más allá de las habituales de una aplicación FiveWin). No está probado con compiladores antiguos.
  2. Pulsar Ejecutar ciclo: aparecen la carpeta temporal del equipo, el nombre creado (prefijo FWE más un número en hexadecimal), los 44 bytes escritos, el contenido releído y el borrado. Si abrís la carpeta temporal después, el archivo ya no está.
  3. Fijaros en el detalle de que la ruta de la carpeta termina en barra, al contrario que la de SHGetKnownFolderPath del ejemplo anterior, que no la lleva.

Validación del ejemplo (medida, no supuesta)

Compilado sin avisos con Harbour (win64) y FWH 26.10, ejecutado en Wine 11.19 el 17 de noviembre; la captura adjunta es de esa corrida en Wine (17/11/2026, no Windows nativo). Valores observados:

  • Ciclo normal: carpeta C:\users\sandbox\AppData\Local\Temp\ (terminada en barra), archivo creado con prefijo FWE, 44 bytes escritos, contenido releído idéntico al escrito y borrado confirmado también por fuera del programa: el archivo ya no existía al terminar. Estado: "Ciclo completo sin errores; no quedan temporales del ejemplo".
  • Cierre sin nada pendiente: tanto el botón Cerrar como un WM_CLOSE enviado a la ventana terminaron con código de salida 0 y sin aviso.

Manejo de errores, probado en copias instrumentadas del ejemplo (no en el publicado, que es el de las capturas normales):

  • Creación sobre una carpeta inexistente: la fila muestra (error 267) y el resto de filas quedan limpias, sin restos de la ejecución anterior.
  • Escritura bloqueada (archivo propio retenido con bloqueo de escritura): la fila indica el fallo de escritura, sin falso éxito, y al desbloquear el ciclo termina limpio.
  • Contenido alterado antes de releer: la comparación detecta que no coincide y lo dice, sin falso éxito.
  • Borrado bloqueado (archivo propio retenido sin compartir borrado): la fila de borrado dice que no, el estado muestra la ruta pendiente y un reintento NO crea otro archivo. Al cerrar con el botón o con WM_CLOSE salta UN solo aviso con la ruta completa del temporal y, tras aceptarlo, el programa termina con código 0. Los archivos retenidos a propósito en estas pruebas quedaron en disco, como avisa el programa, y se borraron después a mano por su ruta exacta.

Ojo con los matices:

  • La corrida fue en Wine 11.19 sin gestor de ventanas: la X real de la barra de título y el Alt+F4 físico no se probaron; el cierre por esa vía se probó enviando el mensaje WM_CLOSE. En Windows nativo puede variar y no lo hemos probado.
  • El pintado del aviso en este entorno no fue uniforme: una captura mostró la ruta parcialmente y otra completa. No afirmamos una representación uniforme en todos los entornos.
  • No se probaron: escritura corta o error de FClose, fallo al abrir para leer, rutas largas o con Unicode, ni fallo de GetTempPath. Cada caso de error se probó una vez (el WM_CLOSE con bloqueo, dos).
  • El aviso deja salir aunque el temporal quede en disco: no hay limpieza garantizada. Y la ruta pendiente se recuerda solo mientras el programa sigue vivo; si se mata el proceso, nada la recuerda.
