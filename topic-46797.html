Primeros pasos con OpenADS (1/5): qué es y cómo empezar

Estimados amigos:

Con esta entrada abrimos una serie divulgativa para quien quiera empezar con OpenADS desde cero, paso a paso y con ejemplos probados antes de publicarse.

¿Qué es OpenADS?

OpenADS es un proyecto libre y de código abierto (licencia MIT en el repositorio actual) del grupo FiveTechSoft en GitHub. Su objetivo declarado es ofrecer un motor compatible con la API de Advantage Database Server (ADS), de forma que las aplicaciones que usaban ace32.dll / ace64.dll puedan seguir funcionando con sus tablas DBF y sus índices (NTX, CDX, ADI).

Es un proyecto en desarrollo activo, así que la regla de oro de esta serie es probar siempre primero en una carpeta nueva con datos de prueba. Nada de tocar la aplicación ni los datos reales como primer paso.

https://github.com/FiveTechSoft/OpenADS

Documentación en español: https://fivetechsoft.github.io/OpenADS/es/

Correccion de licencia: el LICENSE actual del repositorio indica MIT. La etiqueta v1.09.74 usada en estas pruebas conserva un LICENSE Apache 2.0; distinguimos ambas referencias. Disculpad el error en la descripcion inicial.
https://github.com/FiveTechSoft/OpenADS/blob/main/LICENSE
https://github.com/FiveTechSoft/OpenADS/blob/v1.09.74/LICENSE

1. Descargar

Las releases se publican en GitHub con los binarios ya compilados. Al escribir este capítulo la versión actual es la v1.09.74 (12 de octubre de 2026), con estos paquetes:

  • openads-1.09.74-windows-x64.zip : Windows de 64 bits

  • openads-1.09.74-windows-x86.zip : Windows de 32 bits

  • openads-1.09.74-linux-x64.tar.gz : Linux con glibc 2.38 o superior

  • openads-1.09.74-linux-glibc231.tar.gz : Linux con glibc más antigua (por ejemplo Ubuntu 22.04; comprobado que el paquete linux-x64 no arranca ahí)

Página de descargas: https://github.com/FiveTechSoft/OpenADS/releases

2. Qué trae el paquete

Contenido comprobado descomprimiendo los paquetes de la v1.09.74:

  • ace64.dll (o ace32.dll en el paquete x86; libace64.so en Linux) : el motor. Es la pieza que cargan las aplicaciones y la que usaremos en los próximos capítulos, siempre en carpetas de prueba.

  • openace64.dll / openace32.dll / libopenace64.so : el mismo motor con su propio nombre, por si necesita convivir con otra ace64.dll ya instalada.

  • openads_serverd(.exe) : el servidor de red para modo cliente-servidor.

  • openads_bench(.exe) : utilidad de pruebas de carga.

  • lib/ y include/ : librerías de importación (MSVC, MinGW, Borland) y cabeceras para compilar.

  • openads.ini.sample : plantilla comentada de configuración del servidor.

  • QUICKSTART.md y README.md : documentación de arranque incluida en el propio paquete.

Nota: en esta release la consola web Studio no trae script aparte; se arranca desde el propio servidor con la opción --http_port, como veremos ahora mismo.

3. Primera prueba: el servidor y la consola Studio

Vamos a hacer una primera prueba sin tocar ninguna aplicación ni dato existente. Crea una carpeta nueva, por ejemplo openads_prueba, descomprime ahí el paquete y crea dentro una carpeta vacía datos. Desde esa carpeta:

En Linux (comando ejecutado tal cual para este capítulo):

Code: Select all Collapse
./openads_serverd --port 6262 --http_port 6263 --data ./datos

Esta es su salida real, completa:

Code: Select all Collapse
openads_serverd 1.09.74 listening on 127.0.0.1:6262 (backlog=16)
  [dll] no ACE DLL found in working directory (ace64.dll / openace64.dll). AEP external procedures will require an explicit full path.
Studio web console on http://127.0.0.1:6263/  (data=./datos)

La línea "[dll] no ACE DLL found..." es un aviso informativo sobre los procedimientos externos AEP (si algún día los usas, necesitarán ruta explícita); no afecta a servir tablas ni a la consola, y puedes ignorarlo en esta prueba.

En Windows el comando es el mismo con el nombre del ejecutable (lo tomamos de la documentación incluida en el paquete; en esta serie solo lo hemos ejecutado en Linux):

Code: Select all Collapse
openads_serverd.exe --port 6262 --http_port 6263 --data ./datos

En esta prueba (Linux) el servidor escuchó solo en 127.0.0.1, es decir, en la propia máquina, como ves en la salida: perfecto para probar con tranquilidad. Abrirlo a la red lo veremos en el capítulo 4.

Abre http://localhost:6263/ en el navegador y verás la consola Studio con tu carpeta de datos vacía (arriba a la derecha indica "0 tables · ./datos"). Adjuntamos una captura real de esa primera pantalla. Ya tienes OpenADS funcionando. Para parar el servidor, Ctrl+C en su ventana.

Primeros pasos con OpenADS (2/5): tu primera tabla desde Harbour

Estimados amigos:

En el capítulo 1 vimos qué es OpenADS, qué trae la descarga y cómo arrancar el servidor y la consola Studio en una carpeta de prueba. Hoy creamos una tabla DBF desde cero, escribimos registros y los leemos, desde Harbour con el RDD estándar rddads, en modo local (sin servidor). El ejemplo de este capítulo se ha compilado y ejecutado antes de publicarse.

1. Preparar el entorno de compilación (verificado en Linux)

Para compilar el ejemplo necesitas Harbour 3.2 con el contrib rddads construido contra las cabeceras de OpenADS. El rddads de las fuentes de Harbour no compila tal cual contra el ace.h de OpenADS; el propio repositorio publica el ajuste en tools/harbour_patch/rddads-compat.patch.

Prerrequisitos: un compilador de C (gcc), make y git.

a) Raíz del tutorial: una carpeta nueva, para no tocar ninguna instalación previa:

Code: Select all Collapse
mkdir openads_tutorial
cd openads_tutorial

b) Descargar las fuentes de Harbour y de OpenADS:

Code: Select all Collapse
git clone --depth 1 https://github.com/harbour/core harbour
git clone --depth 1 https://github.com/FiveTechSoft/OpenADS openads

Verificado el 20-11-2026 con Harbour revisión 694428e y OpenADS revisión bdb6c1f, más los binarios de la release v1.09.74. Son repositorios vivos: si algo ha cambiado cuando lo leas, el README del parche explica la variante --3way.

Nota de licencia: el paquete v1.09.74 se publicó con licencia Apache 2.0 (https://github.com/FiveTechSoft/OpenADS/blob/v1.09.74/LICENSE) y el repositorio cambió a licencia MIT el 16-11-2026 (https://github.com/FiveTechSoft/OpenADS/blob/main/LICENSE).

c) Compilar el núcleo de Harbour (lleva unos minutos):

Code: Select all Collapse
cd harbour
make -j2

d) Aplicar el parche publicado (desde la carpeta harbour):

Code: Select all Collapse
git apply ../openads/tools/harbour_patch/rddads-compat.patch

Descripción del parche: https://github.com/FiveTechSoft/OpenADS/tree/main/tools/harbour_patch

e) Cabecera puente, solo en Linux (en Windows estos tipos los aporta windows.h). Guardar como ace_shim.h, por ejemplo en la raíz del tutorial:

Code: Select all Collapse
#define VOID void
typedef unsigned short WCHAR;
typedef double DOUBLE;

f) Construir rddads contra las cabeceras del paquete OpenADS. Plantilla (sustituye las dos rutas entre <> por las tuyas). Si seguiste los pasos anteriores estás dentro de la carpeta harbour; desde ahí:

Code: Select all Collapse
cd contrib/rddads
HB_WITH_ADS=<paquete-openads>/include HB_USER_CFLAGS="-include <ruta-tutorial>/ace_shim.h" PATH=../../bin/linux/gcc:$PATH HB_ROOT=../.. hbmk2 rddads.hbp
cp librddads.a ../../lib/linux/gcc/

<paquete-openads> es la carpeta donde descomprimiste la release (capítulo 1); <ruta-tutorial> es la carpeta openads_tutorial. El cp copia la librería dentro del clon nuevo de Harbour del tutorial, no sobre ninguna instalación previa.

Si tu Harbour ya tiene rddads construido contra OpenADS, puedes saltarte los pasos b a f.

2. El programa

Este es exactamente el programa ejecutado; guárdalo como primeratabla.prg. Crea una carpeta exclusiva para cada ejecución (hb_DirCreate solo devuelve 0 si la creamos nosotros; si el nombre existe prueba otro sufijo) y no borra ni sobrescribe nada:

Code: Select all Collapse
/* OpenADS: primeros pasos: crear una tabla, escribir y leer (modo local) */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_paso1"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva de esta ejecucion. hb_DirCreate devuelve 0 solo si
   // la creamos nosotros; si el nombre ya existe, probamos con otro sufijo.
   // Nunca trabajamos sobre una carpeta que no hayamos creado aqui.
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta de prueba exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "clientes.dbf"

   ? "Motor ACE:", AdsVersion()
   ? "Carpeta de prueba:", cDir
   ?

   AdsSetServerType( ADS_LOCAL_SERVER )   // modo local, sin servidor
   AdsSetFileType( ADS_CDX )              // tablas DBF con indices CDX
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )                // "conexion" = carpeta de datos
      ? "AdsConnect fallo:", DosError()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 }, ;
      { "ALTA",    "D",  8, 0 }, ;
      { "ACTIVO",  "L",  1, 0 } } )

   IF ! File( cDbf )
      ? "dbCreate no genero la tabla:", cDbf
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   USE (cDbf) SHARED VIA "ADSCDX"
   IF ! Used()
      ? "No se pudo abrir la tabla"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Garcia, Ana"  ; FIELD->IMPORTE := 1250.75 ; FIELD->ALTA := Date()      ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Lopez, Bruno" ; FIELD->IMPORTE := 980.00  ; FIELD->ALTA := Date() - 15 ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Martin, Carla"; FIELD->IMPORTE := 2330.10 ; FIELD->ALTA := Date() - 40 ; FIELD->ACTIVO := .F.
   DbCommit()

   ? "Registros:", LastRec()
   ?
   ? "Contenido de la tabla:"
   dbGoTop()
   DO WHILE ! Eof()
      ? " ", RecNo(), FIELD->NOMBRE, FIELD->IMPORTE, DToC( FIELD->ALTA ), FIELD->ACTIVO
      dbSkip()
   ENDDO

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

3. Compilar y ejecutar

Plantilla, sustituye las rutas por las tuyas:

Code: Select all Collapse
hbmk2 primeratabla.prg -lrddads -lrddcdx -L<paquete-openads> -lace64 -incpath=<harbour>/contrib/rddads -gtcgi
LD_LIBRARY_PATH=<paquete-openads>:<harbour>/lib/linux/gcc ./primeratabla

-incpath indica dónde está ads.ch; -gtcgi es opcional y solo deja limpia la salida de consola.

En Windows el flujo documentado es el equivalente con MSVC: aplicar el mismo parche, enlazar con ace64.lib y copiar ace64.dll de OpenADS en la carpeta de prueba junto al .exe (según tools/harbour_patch/README.md; en esta serie solo lo hemos ejecutado en Linux).

Ejecutado con Harbour 3.2 y OpenADS v1.09.74 en Linux:

Carpeta de prueba: /tmp/openads_paso1_3

Registros:          3

Contenido de la tabla:
           1 Garcia, Ana                       1250.75 11/20/26 .T.
           2 Lopez, Bruno                       980.00 11/05/26 .T.
           3 Martin, Carla                     2330.10 10/11/26 .F.

Detalles reales de esta ejecución: como ya existían carpetas openads_paso1 de pruebas anteriores, el programa creó openads_paso1_3 (nunca reutiliza una carpeta). Las fechas de ALTA salen de Date(), así que en tu ejecución serán las de ese día.

5. Qué está pasando

  • AdsSetServerType( ADS_LOCAL_SERVER ) : modo local, la propia librería hace de motor, sin servidor de red.

  • AdsSetFileType( ADS_CDX ) y RddSetDefault( "ADSCDX" ) : tablas DBF con índices CDX.

  • AdsConnect( cDir ) : en modo local la conexión es simplemente la carpeta de datos.

  • dbCreate / USE ... VIA "ADSCDX" / DbAppend / FIELD-> : el xBase de siempre. Quien viene de Clipper o Harbour no tiene que aprender sintaxis nueva para estas operaciones.

  • AdsVersion() : la cadena que reporta el motor cargado ("1.9a" con esta release), útil para saber qué librería está usando tu programa.

  • Cada paso comprueba su error (carpeta, conexión, dbCreate, USE) y el programa sale con código de error en vez de continuar como si nada.

Primeros pasos con OpenADS (3/5): índices CDX y búsquedas

Estimados amigos:

En el capítulo 2 creamos una tabla DBF con rddads en modo local. Hoy le añadimos índices CDX, ordenamos con TAG y buscamos con dbSeek. Como toda la serie, el programa de abajo se ha compilado y ejecutado antes de publicarse.

1. El programa

Guárdalo como indices.prg y compílalo con la misma plantilla del capítulo 2 (paso 3). Crea una carpeta exclusiva por ejecución (hb_DirCreate devuelve 0 solo si la crea el programa; si el nombre existe prueba con otro sufijo), con comprobación de error en cada paso y sin borrar ni sobrescribir nada:

Code: Select all Collapse
/* OpenADS: paso 2: indices CDX y busquedas con dbSeek */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_paso2"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva de esta ejecucion. hb_DirCreate devuelve 0 solo si
   // la creamos nosotros; si el nombre ya existe, probamos con otro sufijo.
   // Nunca trabajamos sobre una carpeta que no hayamos creado aqui.
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta de prueba exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "clientes.dbf"

   AdsSetServerType( ADS_LOCAL_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )
      ? "AdsConnect fallo:", DosError()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 }, ;
      { "ACTIVO",  "L",  1, 0 } } )

   IF ! File( cDbf )
      ? "dbCreate no genero la tabla:", cDbf
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   USE (cDbf) SHARED VIA "ADSCDX"
   IF ! Used()
      ? "No se pudo abrir la tabla"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Garcia, Ana"  ; FIELD->IMPORTE := 1250.75 ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Lopez, Bruno" ; FIELD->IMPORTE := 980.00  ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Martin, Carla"; FIELD->IMPORTE := 2330.10 ; FIELD->ACTIVO := .F.
   DbCommit()

   INDEX ON Upper( NOMBRE ) TAG NOMBRE
   INDEX ON IMPORTE TAG IMPORTE
   IF OrdCount() != 2
      ? "Los indices no se crearon bien. Tags:", OrdCount()
      DbCloseArea()
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF
   ? "Tags creados:", OrdCount()

   OrdSetFocus( "NOMBRE" )
   ? "Orden alfabetico (tag NOMBRE):"
   dbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      dbSkip()
   ENDDO

   ?
   OrdSetFocus( "IMPORTE" )
   ? "Orden por importe (tag IMPORTE):"
   dbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      dbSkip()
   ENDDO

   ?
   OrdSetFocus( "NOMBRE" )
   dbSeek( "LOPEZ" )
   ? "dbSeek( 'LOPEZ' ):", iif( Found(), "encontrado en registro " + LTrim( Str( RecNo() ) ), "no encontrado" )

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

2. Salida real

Ejecutado con Harbour 3.2 y OpenADS v1.09.74 en Linux:

Code: Select all Collapse
Tags creados:          2
Orden alfabetico (tag NOMBRE):
   Garcia, Ana                       1250.75
   Lopez, Bruno                       980.00
   Martin, Carla                     2330.10

Orden por importe (tag IMPORTE):
   Lopez, Bruno                       980.00
   Garcia, Ana                       1250.75
   Martin, Carla                     2330.10

dbSeek( 'LOPEZ' ): encontrado en registro 2

3. Qué está pasando

  • INDEX ON Upper( NOMBRE ) TAG NOMBRE : crea el tag NOMBRE dentro del archivo CDX compuesto (un .cdx con varios tags), con clave que ignora mayúsculas gracias a Upper().

  • INDEX ON IMPORTE TAG IMPORTE : un segundo tag en el mismo archivo. OrdCount() confirma que ambos quedaron creados; si no, el programa sale con error.

  • OrdSetFocus( "NOMBRE" ) : cambia el orden activo; dbGoTop()/dbSkip() recorren la tabla en ese orden.

  • dbSeek( "LOPEZ" ) : búsqueda directa por la clave del tag activo (NOMBRE, en mayúsculas por el Upper() de la clave). Found() dice si hubo coincidencia; el programa no imprime éxito si no la hubo.

Primeros pasos con OpenADS (4/5): cliente-servidor por red, solo lectura

Estimados amigos:

En los capítulos 2 y 3 trabajamos en modo local: el propio programa abría los archivos. Ahora pasamos al modo cliente-servidor: arrancamos openads_serverd y nos conectamos por TCP. Para este primer contacto con la red el programa solo consulta: la tabla de ejemplo se crea antes, en modo local y en una carpeta exclusiva, y el cliente remoto la abre, la recorre y busca, sin crear ni modificar nada. Al final comprobamos con md5 que los archivos del servidor quedaron byte a byte iguales. Todo lo que sigue se ha ejecutado de verdad.

1. Preparación: crear la tabla de ejemplo en local

Este primer programa crea una carpeta exclusiva (hb_DirCreate solo devuelve 0 si la crea el propio programa; si el nombre existe prueba con otro sufijo) y dentro la tabla demo_red con dos registros y un tag CDX. Es el mismo xBase de los capítulos anteriores, en modo local:

Code: Select all Collapse
/* OpenADS: paso 3, preparacion: crea la tabla de ejemplo en MODO LOCAL */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_srv"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva creada por este programa (nunca una ajena)
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "demo_red"

   AdsSetServerType( ADS_LOCAL_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )
      ? "AdsConnect fallo."
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 } } )

   USE (cDbf) VIA "ADSCDX" NEW EXCLUSIVE
   IF ! Used()
      ? "No se pudo crear la tabla de ejemplo."
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Via red 1"; FIELD->IMPORTE := 100.00
   DbAppend(); FIELD->NOMBRE := "Via red 2"; FIELD->IMPORTE := 200.00
   DbCommit()
   INDEX ON Upper( NOMBRE ) TAG NOMBRE

   ? "Registros preparados:", LastRec()
   DbCloseArea()
   AdsDisconnect()

   ? "Carpeta del servidor:", cDir
   ? "Fin."
   RETURN

Salida real:

Code: Select all Collapse
Registros preparados:          2
Carpeta del servidor: /tmp/openads_srv
Fin.

Anota la carpeta que imprima tu ejecución: es la que usará el servidor.

2. Arrancar el servidor sobre esa carpeta

Comando literal usado en la prueba, ejecutado desde la carpeta donde descomprimiste el paquete OpenADS:

Code: Select all Collapse
./openads_serverd --port 6262 --http_port 6263 --data /tmp/openads_srv

El servidor confirma en consola que escucha en 127.0.0.1:6262 y que su carpeta de datos es /tmp/openads_srv. Como en el capítulo 1, trabajamos solo en loopback: antes de abrir el servidor a la red, consulta en la documentación las opciones de usuarios, contraseñas y conexión cifrada: https://fivetechsoft.github.io/OpenADS/es/

3. El cliente remoto

Code: Select all Collapse
/* OpenADS: paso 3: lectura cliente-servidor por TCP (solo lectura) */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main( cSrvDir )

   LOCAL cTab := "demo_red"
   LOCAL bOld, lOk

   IF Empty( cSrvDir )
      ? "Uso: paso3 <carpeta-datos-del-servidor>"
      ? "La misma carpeta que se paso al servidor con --data"
      ErrorLevel( 1 )
      QUIT
   ENDIF

   AdsSetServerType( ADS_REMOTE_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   ? "Conectando a tcp://127.0.0.1:6262/" + cSrvDir
   IF ! AdsConnect( "tcp://127.0.0.1:6262/" + cSrvDir )
      ? "AdsConnect fallo. Servidor arrancado? Carpeta correcta?"
      ErrorLevel( 1 )
      QUIT
   ENDIF
   ? "Conectado."

   // Abrimos la tabla EXISTENTE a traves de la conexion. Este cliente
   // no crea nada: si la tabla no esta, termina con error.
   bOld := ErrorBlock( {| e | Break( e ) } )
   lOk := .T.
   BEGIN SEQUENCE
      USE (cTab) SHARED VIA "ADSCDX" NEW INDEX (cTab)
   RECOVER
      lOk := .F.
   END SEQUENCE
   ErrorBlock( bOld )

   IF ! lOk
      ? "No se pudo abrir la tabla", cTab, "en el servidor. Ejecutaste la preparacion?"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF
   ? "Tabla abierta:", cTab, "con", LastRec(), "registros"

   DbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      DbSkip()
   ENDDO

   dbSeek( "VIA RED 2" )
   ? "dbSeek:", iif( Found(), "encontrado registro " + LTrim( Str( RecNo() ) ), "no encontrado" )

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

Puntos importantes del código:

  • El cliente no crea nada: si la tabla no está en el servidor, termina con mensaje y código de error. No hay dbCreate remoto en este capítulo.

  • AdsSetServerType( ADS_REMOTE_SERVER ) : las operaciones van por la red al proceso servidor.

  • AdsConnect( "tcp://IP:PUERTO//RUTA" ) : la ruta es del lado del servidor (la carpeta --data), con doble barra antes de ella cuando es absoluta.

  • USE ( cTab ) : tras conectar, el nombre de tabla se resuelve en el servidor a través de la conexión activa; el cliente no toca archivos locales.

  • INDEX ( cTab ) : en nuestras pruebas la apertura remota no activó el índice CDX automáticamente (dbSeek devolvía el error ADSCDX/301 "Workarea not indexed"); lo abrimos de forma explícita junto al USE.

Primeros pasos con OpenADS (5/5): SQL local desde Harbour

Estimados amigos:

Cerramos la serie con el tercer camino de acceso: SQL. La librería rddads que construimos en el capítulo 2 expone también la API SQL del motor (AdsCreateSQLStatement / AdsExecuteSQLDirect), que permite lanzar consultas SQL sobre las tablas. El ejemplo crea su tabla dentro de una carpeta exclusiva por ejecución (como en los capítulos anteriores, nunca sobre archivos ajenos), la rellena por xBase y ejecuta un SELECT con filtro y orden. Compilado y ejecutado antes de publicarse.

1. El programa

Code: Select all Collapse
/* OpenADS: paso 4: SQL sobre tablas DBF libres */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_paso4"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva de esta ejecucion. hb_DirCreate devuelve 0 solo si
   // la creamos nosotros; si el nombre ya existe, probamos con otro sufijo.
   // Nunca trabajamos sobre una carpeta que no hayamos creado aqui.
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta de prueba exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "clientes.dbf"

   AdsSetServerType( ADS_LOCAL_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )
      ? "AdsConnect fallo:", DosError()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 }, ;
      { "ACTIVO",  "L",  1, 0 } } )

   IF ! File( cDbf )
      ? "dbCreate no genero la tabla:", cDbf
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   USE (cDbf) SHARED VIA "ADSCDX"
   IF ! Used()
      ? "No se pudo abrir la tabla"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Garcia, Ana"  ; FIELD->IMPORTE := 1250.75 ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Lopez, Bruno" ; FIELD->IMPORTE := 980.00  ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Martin, Carla"; FIELD->IMPORTE := 2330.10 ; FIELD->ACTIVO := .F.
   DbCommit()
   DbCloseArea()

   IF ! AdsCreateSQLStatement( "QRY", ADS_CDX )
      ? "No se pudo crear el statement SQL"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   SELECT QRY
   IF ! AdsExecuteSQLDirect( "SELECT NOMBRE, IMPORTE FROM clientes WHERE IMPORTE > 1000 ORDER BY IMPORTE DESC" )
      ? "Error al ejecutar el SQL"
      DbCloseArea()
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   ? "Clientes con importe > 1000, de mayor a menor:"
   dbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      dbSkip()
   ENDDO

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

2. Salida real

Ejecutado con Harbour 3.2 y OpenADS v1.09.74 en Linux:

Code: Select all Collapse
Clientes con importe > 1000, de mayor a menor:
   Martin, Carla                     2330.10
   Garcia, Ana                       1250.75
Fin.

3. Qué está pasando

  • AdsCreateSQLStatement( "QRY", ADS_CDX ) : crea un statement SQL y lo expone como el área de trabajo QRY; el segundo parámetro indica que trabajamos con tablas DBF libres.

  • SELECT QRY y AdsExecuteSQLDirect( "SELECT ..." ) : ejecuta la consulta y deja el cursor del resultado en QRY, que recorremos con dbGoTop()/dbSkip(). El motor evalúa el WHERE y el ORDER BY, no el cliente registro a registro.

  • Comprobamos el retorno de ambas llamadas SQL: si alguna falla, mensaje y salida con código de error en vez de continuar.

  • La misma plantilla de compilación del capítulo 2 (paso 3) sirve sin cambios: estas funciones vienen en la librería rddads construida allí, verificado al compilar este ejemplo.

  • Ámbito probado: SQL local sobre tablas DBF libres. El SQL remoto por TCP no se cubre en esta serie.
