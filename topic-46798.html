Getting started with OpenADS (1/5): what it is and how to begin

Dear friends:

With this post we open a tutorial series for anyone who wants to start with OpenADS from scratch, step by step, with examples tested before publishing.

What is OpenADS?

OpenADS is a free, open-source project (MIT license in the current repository) from the FiveTechSoft group on GitHub. Its stated goal is to provide an engine compatible with the Advantage Database Server (ADS) API, so applications that used ace32.dll / ace64.dll can keep working with their DBF tables and indexes (NTX, CDX, ADI).

It is under active development, so the golden rule of this series is to always test first in a new folder with test data. Never start by touching your application or your real data.

https://github.com/FiveTechSoft/OpenADS

Documentation: https://fivetechsoft.github.io/OpenADS/en/

License correction: the current repository LICENSE states MIT. The v1.09.74 tag used in these tests retains an Apache 2.0 LICENSE; these are separate references. Sorry for the error in the initial description.
https://github.com/FiveTechSoft/OpenADS/blob/main/LICENSE
https://github.com/FiveTechSoft/OpenADS/blob/v1.09.74/LICENSE

1. Download

Releases are published on GitHub with ready-made binaries. As of this writing the current version is v1.09.74 (October 12, 2026), with these packages:

  • openads-1.09.74-windows-x64.zip : 64-bit Windows

  • openads-1.09.74-windows-x86.zip : 32-bit Windows

  • openads-1.09.74-linux-x64.tar.gz : Linux with glibc 2.38 or newer

  • openads-1.09.74-linux-glibc231.tar.gz : Linux with an older glibc (for example Ubuntu 22.04; we checked the linux-x64 package does not start there)

Downloads page: https://github.com/FiveTechSoft/OpenADS/releases

2. What is in the package

Contents checked by extracting the v1.09.74 packages:

  • ace64.dll (or ace32.dll in the x86 package; libace64.so on Linux) : the engine. This is the piece applications load, and the one we will use in the next chapters, always in test folders.

  • openace64.dll / openace32.dll / libopenace64.so : the same engine under its own name, in case it must coexist with another ace64.dll already installed.

  • openads_serverd(.exe) : the network server for client-server mode.

  • openads_bench(.exe) : load testing utility.

  • lib/ and include/ : import libraries (MSVC, MinGW, Borland) and headers for building.

  • openads.ini.sample : commented server configuration template.

  • QUICKSTART.md and README.md : startup documentation included in the package itself.

Note: in this release the Studio web console has no separate script; it is started from the server itself with the --http_port option, as we will see right now.

3. First test: the server and the Studio console

Let's do a first test without touching any existing application or data. Create a new folder, for example openads_test, extract the package there and create an empty datos folder inside. From that folder:

On Linux (command run exactly as shown for this chapter):

Code: Select all Collapse
./openads_serverd --port 6262 --http_port 6263 --data ./datos

This is its real output, in full:

Code: Select all Collapse
openads_serverd 1.09.74 listening on 127.0.0.1:6262 (backlog=16)
  [dll] no ACE DLL found in working directory (ace64.dll / openace64.dll). AEP external procedures will require an explicit full path.
Studio web console on http://127.0.0.1:6263/  (data=./datos)

The "[dll] no ACE DLL found..." line is an informational notice about AEP external procedures (if you ever use them, they will need an explicit path); it does not affect serving tables or the console, and you can ignore it in this test.

On Windows the command is the same with the executable name (taken from the documentation included in the package; in this series we have only run it on Linux):

Code: Select all Collapse
openads_serverd.exe --port 6262 --http_port 6263 --data ./datos

In this test (Linux) the server listened only on 127.0.0.1, that is, on the machine itself, as you can see in the output: perfect for testing with peace of mind. Opening it to the network is covered in chapter 4.

Open http://localhost:6263/ in your browser and you will see the Studio console with your empty data folder (top right shows "0 tables · ./datos"). We attach a real screenshot of that first screen. OpenADS is now running. To stop the server, press Ctrl+C in its window.

Getting started with OpenADS (2/5): your first table from Harbour

Dear friends:

In chapter 1 we saw what OpenADS is, what the download includes and how to start the server and the Studio console in a test folder. Today we create a DBF table from scratch, write records and read them back, from Harbour with the standard rddads RDD, in local mode (no server). This chapter's example was compiled and run before publishing.

1. Setting up the build environment (verified on Linux)

To build the example you need Harbour 3.2 with the rddads contrib built against the OpenADS headers. Harbour's rddads sources do not compile as-is against OpenADS' ace.h; the repository itself publishes the adjustment in tools/harbour_patch/rddads-compat.patch.

Prerequisites: a C compiler (gcc), make and git.

a) Tutorial root: a new folder, so no previous installation is touched:

Code: Select all Collapse
mkdir openads_tutorial
cd openads_tutorial

b) Download the Harbour and OpenADS sources:

Code: Select all Collapse
git clone --depth 1 https://github.com/harbour/core harbour
git clone --depth 1 https://github.com/FiveTechSoft/OpenADS openads

Verified on 2026-11-20 with Harbour revision 694428e and OpenADS revision bdb6c1f, plus the v1.09.74 release binaries. These are moving repositories: if something has changed by the time you read this, the patch README explains the --3way variant.

License note: the v1.09.74 package was published under the Apache 2.0 license (https://github.com/FiveTechSoft/OpenADS/blob/v1.09.74/LICENSE) and the repository switched to the MIT license on 2026-11-16 (https://github.com/FiveTechSoft/OpenADS/blob/main/LICENSE).

c) Build the Harbour core (takes a few minutes):

Code: Select all Collapse
cd harbour
make -j2

d) Apply the published patch (from the harbour folder):

Code: Select all Collapse
git apply ../openads/tools/harbour_patch/rddads-compat.patch

Patch description: https://github.com/FiveTechSoft/OpenADS/tree/main/tools/harbour_patch

e) Bridge header, Linux only (on Windows these types come from windows.h). Save as ace_shim.h, for example in the tutorial root:

Code: Select all Collapse
#define VOID void
typedef unsigned short WCHAR;
typedef double DOUBLE;

f) Build rddads against the OpenADS package headers. Template (replace the two paths between <> with yours). If you followed the previous steps you are inside the harbour folder; from there:

Code: Select all Collapse
cd contrib/rddads
HB_WITH_ADS=<openads-package>/include HB_USER_CFLAGS="-include <tutorial-path>/ace_shim.h" PATH=../../bin/linux/gcc:$PATH HB_ROOT=../.. hbmk2 rddads.hbp
cp librddads.a ../../lib/linux/gcc/

<openads-package> is the folder where you extracted the release (chapter 1); <tutorial-path> is the openads_tutorial folder. The cp copies the library into the tutorial's fresh Harbour clone, not over any previous installation.

If your Harbour already has rddads built against OpenADS, you can skip steps b to f.

2. The program

This is exactly the program that was run; save it as primeratabla.prg. It creates an exclusive folder for each run (hb_DirCreate only returns 0 if we created it ourselves; if the name exists it tries another suffix) and it never deletes or overwrites anything:

Code: Select all Collapse
/* OpenADS: primeros pasos: crear una tabla, escribir y leer (modo local) */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_paso1"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva de esta ejecucion. hb_DirCreate devuelve 0 solo si
   // la creamos nosotros; si el nombre ya existe, probamos con otro sufijo.
   // Nunca trabajamos sobre una carpeta que no hayamos creado aqui.
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta de prueba exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "clientes.dbf"

   ? "Motor ACE:", AdsVersion()
   ? "Carpeta de prueba:", cDir
   ?

   AdsSetServerType( ADS_LOCAL_SERVER )   // modo local, sin servidor
   AdsSetFileType( ADS_CDX )              // tablas DBF con indices CDX
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )                // "conexion" = carpeta de datos
      ? "AdsConnect fallo:", DosError()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 }, ;
      { "ALTA",    "D",  8, 0 }, ;
      { "ACTIVO",  "L",  1, 0 } } )

   IF ! File( cDbf )
      ? "dbCreate no genero la tabla:", cDbf
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   USE (cDbf) SHARED VIA "ADSCDX"
   IF ! Used()
      ? "No se pudo abrir la tabla"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Garcia, Ana"  ; FIELD->IMPORTE := 1250.75 ; FIELD->ALTA := Date()      ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Lopez, Bruno" ; FIELD->IMPORTE := 980.00  ; FIELD->ALTA := Date() - 15 ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Martin, Carla"; FIELD->IMPORTE := 2330.10 ; FIELD->ALTA := Date() - 40 ; FIELD->ACTIVO := .F.
   DbCommit()

   ? "Registros:", LastRec()
   ?
   ? "Contenido de la tabla:"
   dbGoTop()
   DO WHILE ! Eof()
      ? " ", RecNo(), FIELD->NOMBRE, FIELD->IMPORTE, DToC( FIELD->ALTA ), FIELD->ACTIVO
      dbSkip()
   ENDDO

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

3. Build and run

Template, replace the paths with yours:

Code: Select all Collapse
hbmk2 primeratabla.prg -lrddads -lrddcdx -L<openads-package> -lace64 -incpath=<harbour>/contrib/rddads -gtcgi
LD_LIBRARY_PATH=<openads-package>:<harbour>/lib/linux/gcc ./primeratabla

-incpath says where ads.ch lives; -gtcgi is optional and just keeps console output clean.

On Windows the documented flow is the MSVC equivalent: apply the same patch, link with ace64.lib and copy OpenADS' ace64.dll into the test folder next to the .exe (per tools/harbour_patch/README.md; in this series we have only run it on Linux).

4. Real program output

Run with Harbour 3.2 and OpenADS v1.09.74 on Linux:

Code: Select all Collapse
Motor ACE: 1.9a
Carpeta de prueba: /tmp/openads_paso1_3

Registros:          3

Contenido de la tabla:
           1 Garcia, Ana                       1250.75 11/20/26 .T.
           2 Lopez, Bruno                       980.00 11/05/26 .T.
           3 Martin, Carla                     2330.10 10/11/26 .F.
Fin.

Real details of this run: since openads_paso1 folders from earlier tests already existed, the program created openads_paso1_3 (it never reuses a folder). The ALTA dates come from Date(), so your run will show that day's dates.

5. What is going on

  • AdsSetServerType( ADS_LOCAL_SERVER ) : local mode, the library itself acts as the engine, no network server.

  • AdsSetFileType( ADS_CDX ) and RddSetDefault( "ADSCDX" ) : DBF tables with CDX indexes.

  • AdsConnect( cDir ) : in local mode the connection is simply the data folder.

  • dbCreate / USE ... VIA "ADSCDX" / DbAppend / FIELD-> : the usual xBase. Anyone coming from Clipper or Harbour does not need to learn new syntax for these operations.

  • AdsVersion() : the string reported by the loaded engine ("1.9a" with this release), useful to know which library your program is using.

  • Every step checks its error (folder, connection, dbCreate, USE) and the program exits with an error code instead of carrying on as if nothing happened.

Getting started with OpenADS (3/5): CDX indexes and searches

Dear friends:

In chapter 2 we created a DBF table with rddads in local mode. Today we add CDX indexes, sort with TAG and search with dbSeek. As in the whole series, the program below was compiled and run before publishing.

1. The program

Save it as indices.prg and build it with the same template from chapter 2 (step 3). It creates an exclusive folder per run (hb_DirCreate returns 0 only if the program created it; if the name exists it tries another suffix), checks errors at every step and never deletes or overwrites anything:

Code: Select all Collapse
/* OpenADS: paso 2: indices CDX y busquedas con dbSeek */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_paso2"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva de esta ejecucion. hb_DirCreate devuelve 0 solo si
   // la creamos nosotros; si el nombre ya existe, probamos con otro sufijo.
   // Nunca trabajamos sobre una carpeta que no hayamos creado aqui.
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta de prueba exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "clientes.dbf"

   AdsSetServerType( ADS_LOCAL_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )
      ? "AdsConnect fallo:", DosError()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 }, ;
      { "ACTIVO",  "L",  1, 0 } } )

   IF ! File( cDbf )
      ? "dbCreate no genero la tabla:", cDbf
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   USE (cDbf) SHARED VIA "ADSCDX"
   IF ! Used()
      ? "No se pudo abrir la tabla"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Garcia, Ana"  ; FIELD->IMPORTE := 1250.75 ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Lopez, Bruno" ; FIELD->IMPORTE := 980.00  ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Martin, Carla"; FIELD->IMPORTE := 2330.10 ; FIELD->ACTIVO := .F.
   DbCommit()

   INDEX ON Upper( NOMBRE ) TAG NOMBRE
   INDEX ON IMPORTE TAG IMPORTE
   IF OrdCount() != 2
      ? "Los indices no se crearon bien. Tags:", OrdCount()
      DbCloseArea()
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF
   ? "Tags creados:", OrdCount()

   OrdSetFocus( "NOMBRE" )
   ? "Orden alfabetico (tag NOMBRE):"
   dbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      dbSkip()
   ENDDO

   ?
   OrdSetFocus( "IMPORTE" )
   ? "Orden por importe (tag IMPORTE):"
   dbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      dbSkip()
   ENDDO

   ?
   OrdSetFocus( "NOMBRE" )
   dbSeek( "LOPEZ" )
   ? "dbSeek( 'LOPEZ' ):", iif( Found(), "encontrado en registro " + LTrim( Str( RecNo() ) ), "no encontrado" )

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

2. Real output

Run with Harbour 3.2 and OpenADS v1.09.74 on Linux:

Code: Select all Collapse
Tags creados:          2
Orden alfabetico (tag NOMBRE):
   Garcia, Ana                       1250.75
   Lopez, Bruno                       980.00
   Martin, Carla                     2330.10

Orden por importe (tag IMPORTE):
   Lopez, Bruno                       980.00
   Garcia, Ana                       1250.75
   Martin, Carla                     2330.10

dbSeek( 'LOPEZ' ): encontrado en registro 2
Fin.

3. What is going on

  • INDEX ON Upper( NOMBRE ) TAG NOMBRE : creates the NOMBRE tag inside the compound CDX file (one .cdx holding several tags), with a case-insensitive key thanks to Upper().

  • INDEX ON IMPORTE TAG IMPORTE : a second tag in the same file. OrdCount() confirms both were created; otherwise the program exits with an error.

  • OrdSetFocus( "NOMBRE" ) : switches the active order; dbGoTop()/dbSkip() walk the table in that order.

  • dbSeek( "LOPEZ" ) : direct lookup by the active tag's key (NOMBRE, uppercase because of the key's Upper()). Found() says whether there was a match; the program does not print success when there was none.

Getting started with OpenADS (4/5): client-server over the network, read-only

Dear friends:

In chapters 2 and 3 we worked in local mode: the program itself opened the files. Now we switch to client-server mode: we start openads_serverd and connect over TCP. For this first contact with the network the program only queries: the sample table is created beforehand, in local mode and in an exclusive folder, and the remote client opens it, walks it and searches, without creating or modifying anything. At the end we verify with md5 that the server files stayed byte-identical. Everything below was actually run.

1. Preparation: create the sample table locally

This first program creates an exclusive folder (hb_DirCreate only returns 0 if the program itself created it; if the name exists it tries another suffix) and inside it the demo_red table with two records and a CDX tag. It is the same xBase as in the previous chapters, in local mode:

Code: Select all Collapse
/* OpenADS: paso 3, preparacion: crea la tabla de ejemplo en MODO LOCAL */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_srv"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva creada por este programa (nunca una ajena)
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "demo_red"

   AdsSetServerType( ADS_LOCAL_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )
      ? "AdsConnect fallo."
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 } } )

   USE (cDbf) VIA "ADSCDX" NEW EXCLUSIVE
   IF ! Used()
      ? "No se pudo crear la tabla de ejemplo."
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Via red 1"; FIELD->IMPORTE := 100.00
   DbAppend(); FIELD->NOMBRE := "Via red 2"; FIELD->IMPORTE := 200.00
   DbCommit()
   INDEX ON Upper( NOMBRE ) TAG NOMBRE

   ? "Registros preparados:", LastRec()
   DbCloseArea()
   AdsDisconnect()

   ? "Carpeta del servidor:", cDir
   ? "Fin."
   RETURN

Real output:

Code: Select all Collapse
Registros preparados:          2
Carpeta del servidor: /tmp/openads_srv
Fin.

Note down the folder your run prints: it is the one the server will use.

2. Start the server on that folder

Literal command used in the test, run from the folder where you extracted the OpenADS package:

Code: Select all Collapse
./openads_serverd --port 6262 --http_port 6263 --data /tmp/openads_srv

The server confirms on its console that it listens on 127.0.0.1:6262 and that its data folder is /tmp/openads_srv. As in chapter 1, we work on loopback only: before exposing the server to the network, check the documentation for the user, password and encrypted connection options: https://fivetechsoft.github.io/OpenADS/es/

3. The remote client

Code: Select all Collapse
/* OpenADS: paso 3: lectura cliente-servidor por TCP (solo lectura) */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main( cSrvDir )

   LOCAL cTab := "demo_red"
   LOCAL bOld, lOk

   IF Empty( cSrvDir )
      ? "Uso: paso3 <carpeta-datos-del-servidor>"
      ? "La misma carpeta que se paso al servidor con --data"
      ErrorLevel( 1 )
      QUIT
   ENDIF

   AdsSetServerType( ADS_REMOTE_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   ? "Conectando a tcp://127.0.0.1:6262/" + cSrvDir
   IF ! AdsConnect( "tcp://127.0.0.1:6262/" + cSrvDir )
      ? "AdsConnect fallo. Servidor arrancado? Carpeta correcta?"
      ErrorLevel( 1 )
      QUIT
   ENDIF
   ? "Conectado."

   // Abrimos la tabla EXISTENTE a traves de la conexion. Este cliente
   // no crea nada: si la tabla no esta, termina con error.
   bOld := ErrorBlock( {| e | Break( e ) } )
   lOk := .T.
   BEGIN SEQUENCE
      USE (cTab) SHARED VIA "ADSCDX" NEW INDEX (cTab)
   RECOVER
      lOk := .F.
   END SEQUENCE
   ErrorBlock( bOld )

   IF ! lOk
      ? "No se pudo abrir la tabla", cTab, "en el servidor. Ejecutaste la preparacion?"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF
   ? "Tabla abierta:", cTab, "con", LastRec(), "registros"

   DbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      DbSkip()
   ENDDO

   dbSeek( "VIA RED 2" )
   ? "dbSeek:", iif( Found(), "encontrado registro " + LTrim( Str( RecNo() ) ), "no encontrado" )

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

Important points in the code:

  • The client creates nothing: if the table is not on the server, it ends with a message and an error code. There is no remote dbCreate in this chapter.

  • AdsSetServerType( ADS_REMOTE_SERVER ) : operations go over the network to the server process.

  • AdsConnect( "tcp://IP:PORT//PATH" ) : the path is on the server side (the --data folder), with a double slash before it when absolute.

  • USE ( cTab ) : once connected, the table name is resolved on the server through the active connection; the client does not touch local files.

  • INDEX ( cTab ) : in our tests the remote open did not attach the CDX index automatically (dbSeek failed with error ADSCDX/301 "Workarea not indexed"); we open it explicitly together with the USE.

4. Build and run

Build template (same as chapter 2; replace the paths between <> with yours), once per program:

Code: Select all Collapse
hbmk2 paso3prep.prg -lrddads -lrddcdx -L<openads-package> -lace64 -incpath=<harbour>/contrib/rddads -gtcgi
hbmk2 paso3.prg -lrddads -lrddcdx -L<openads-package> -lace64 -incpath=<harbour>/contrib/rddads -gtcgi

Full order followed in the test (with LD_LIBRARY_PATH pointing at the OpenADS package and the Harbour libraries, as in chapter 2):

Code: Select all Collapse
./paso3prep
./openads_serverd --port 6262 --http_port 6263 --data /tmp/openads_srv
./paso3 /tmp/openads_srv

The sequence matters: 1) build both programs, 2) run paso3prep ONCE and note the folder it prints (running it again creates another suffixed folder), 3) start the server with that folder in --data and leave it running in another console, 4) run the client passing it the same folder.

6. What is going on

  • The DBF/CDX files live in the server's folder; the client only sends operations over TCP.

  • SHARED opens the table in shared mode; this example uses a single client.

  • dbSeek works the same as locally (chapter 3) once the index is open.

Getting started with OpenADS (5/5): local SQL from Harbour

Dear friends:

We close the series with the third access path: SQL. The rddads library we built in chapter 2 also exposes the engine's SQL API (AdsCreateSQLStatement / AdsExecuteSQLDirect), which lets you run SQL queries over the tables. The example creates its table inside an exclusive per-run folder (as in previous chapters, never over anyone else's files), fills it the xBase way and runs a SELECT with a filter and ordering. Compiled and run before publishing.

1. The program

Code: Select all Collapse
/* OpenADS: paso 4: SQL sobre tablas DBF libres */
#include "ads.ch"

REQUEST ADS, ADSCDX

PROCEDURE Main()

   LOCAL cBase := hb_DirTemp() + "openads_paso4"
   LOCAL cDir  := cBase
   LOCAL n     := 1
   LOCAL nRC
   LOCAL cDbf

   // Carpeta exclusiva de esta ejecucion. hb_DirCreate devuelve 0 solo si
   // la creamos nosotros; si el nombre ya existe, probamos con otro sufijo.
   // Nunca trabajamos sobre una carpeta que no hayamos creado aqui.
   nRC := hb_DirCreate( cDir )
   DO WHILE nRC != 0 .AND. n < 100
      n := n + 1
      cDir := cBase + "_" + LTrim( Str( n ) )
      nRC := hb_DirCreate( cDir )
   ENDDO
   IF nRC != 0
      ? "No se pudo crear una carpeta de prueba exclusiva. Error:", nRC
      ErrorLevel( 1 )
      QUIT
   ENDIF

   cDbf := cDir + hb_ps() + "clientes.dbf"

   AdsSetServerType( ADS_LOCAL_SERVER )
   AdsSetFileType( ADS_CDX )
   RddSetDefault( "ADSCDX" )

   IF ! AdsConnect( cDir )
      ? "AdsConnect fallo:", DosError()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   dbCreate( cDbf, { ;
      { "NOMBRE",  "C", 30, 0 }, ;
      { "IMPORTE", "N", 10, 2 }, ;
      { "ACTIVO",  "L",  1, 0 } } )

   IF ! File( cDbf )
      ? "dbCreate no genero la tabla:", cDbf
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   USE (cDbf) SHARED VIA "ADSCDX"
   IF ! Used()
      ? "No se pudo abrir la tabla"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   DbAppend(); FIELD->NOMBRE := "Garcia, Ana"  ; FIELD->IMPORTE := 1250.75 ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Lopez, Bruno" ; FIELD->IMPORTE := 980.00  ; FIELD->ACTIVO := .T.
   DbAppend(); FIELD->NOMBRE := "Martin, Carla"; FIELD->IMPORTE := 2330.10 ; FIELD->ACTIVO := .F.
   DbCommit()
   DbCloseArea()

   IF ! AdsCreateSQLStatement( "QRY", ADS_CDX )
      ? "No se pudo crear el statement SQL"
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   SELECT QRY
   IF ! AdsExecuteSQLDirect( "SELECT NOMBRE, IMPORTE FROM clientes WHERE IMPORTE > 1000 ORDER BY IMPORTE DESC" )
      ? "Error al ejecutar el SQL"
      DbCloseArea()
      AdsDisconnect()
      ErrorLevel( 1 )
      QUIT
   ENDIF

   ? "Clientes con importe > 1000, de mayor a menor:"
   dbGoTop()
   DO WHILE ! Eof()
      ? "  ", FIELD->NOMBRE, FIELD->IMPORTE
      dbSkip()
   ENDDO

   DbCloseArea()
   AdsDisconnect()
   ? "Fin."
   RETURN

2. Real output

Run with Harbour 3.2 and OpenADS v1.09.74 on Linux:

Code: Select all Collapse
Clientes con importe > 1000, de mayor a menor:
   Martin, Carla                     2330.10
   Garcia, Ana                       1250.75
Fin.

3. What is going on

  • AdsCreateSQLStatement( "QRY", ADS_CDX ) : creates a SQL statement and exposes it as the QRY workarea; the second parameter says we work with free DBF tables.

  • SELECT QRY and AdsExecuteSQLDirect( "SELECT ..." ) : runs the query and leaves the result cursor in QRY, which we walk with dbGoTop()/dbSkip(). The engine evaluates the WHERE and the ORDER BY, not the client record by record.

  • We check the return of both SQL calls: if one fails, message and exit with an error code instead of carrying on.

  • The same build template from chapter 2 (step 3) works unchanged: these functions come in the rddads library built there, verified when compiling this example.

  • Verified scope: local SQL over free DBF tables. Remote SQL over TCP is not covered in this series.
