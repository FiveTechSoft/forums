Temporizadores esperables del kernel con CreateWaitableTimer

Hola a todos:

Seguimos con la serie de ejemplos de programación Windows con FiveWin. Hoy, una pieza del kernel poco vista en ejemplos de GUI: los temporizadores esperables. Un TIMER de FiveWin (o el SetTimer de la API) avisa con mensajes WM_TIMER en el bucle de la ventana; CreateWaitableTimer crea en cambio un objeto del kernel, con handle, que se espera como un evento o un mutex.

Lo que dice la documentación de Microsoft

  • Se crea con CreateWaitableTimer (manual-reset o auto-reset) y se activa con SetWaitableTimer.
  • El "due time" va en intervalos de 100 nanosegundos: negativo para tiempo relativo, positivo para hora absoluta UTC.
  • lPeriod va en milisegundos: 0 dispara una sola vez; mayor que 0 lo hace periódico hasta cancelarlo o reactivarlo.
  • Con un temporizador auto-reset, cada espera que lo ve señalizado consume la señal. La variante manual-reset queda señalizada hasta la próxima llamada a SetWaitableTimer.
  • Llamar a SetWaitableTimer sobre un temporizador activo lo detiene y lo reactiva.
  • CancelWaitableTimer lo deja inactivo y no cambia su estado de señalización.
  • Requiere Windows XP o superior; al compilar, el SDK debe definir _WIN32_WINNT >= 0x0400. La API vive en kernel32: no hacen falta librerías extra.

El ejemplo completo

Nota sobre la referencia en la cabecera del PRG: conserva un enlace a CreateWaitableTimerExW, pero el código usa CreateWaitableTimerA, la API clásica ANSI, sin la variante Ex. La referencia correcta para la API clásica figura al final.

Una ventana con tres botones: un temporizador de disparo único a los 3 segundos, uno periódico cada segundo y un botón Cancelar. Como el temporizador del kernel no manda mensajes, un TIMER de FiveWin sondea su estado cada 100 ms con WaitForSingleObject(hTimer, 0), que no bloquea el bucle de mensajes: cuando el kernel lo marca señalizado, el programa anota el disparo y la hora. El código C embebido va en el propio PRG y mantiene el handle (WT_Start, WT_Poll, WT_Cancel, WT_Destroy, WT_LastError).

//----------------------------------------------------------------------------//
// WTIMER.PRG (v2)
// Temporizador esperable del kernel con CreateWaitableTimer
// Ejemplo didactico FiveWin (FWH) + Harbour
//
// Que muestra:
//   - CreateWaitableTimer: el temporizador es un objeto del kernel,
//     con handle, como un evento o un mutex (doc. Microsoft)
//   - SetWaitableTimer: due time en intervalos de 100 ns; negativo =
//     tiempo relativo, positivo = hora absoluta UTC. Aqui usamos
//     relativo. lPeriod en ms: 0 = disparo unico, >0 = periodico
//     (doc. Microsoft)
//   - WaitForSingleObject( hTimer, 0 ): sondeo sin bloqueo del estado
//     señalizado. Con un temporizador de auto-reset (como el de este
//     ejemplo) cada espera que lo ve señalizado consume la señal
//     (doc. Microsoft)
//   - CancelWaitableTimer: deja el temporizador inactivo
//
// El ejemplo crea el temporizador de auto-reset (bManualReset = FALSE).
// La variante manual-reset queda señalizada hasta la proxima llamada a
// SetWaitableTimer (doc. Microsoft); aqui no se usa.
//
// El sondeo lo hace un TIMER de FiveWin cada 100 ms: el temporizador
// del kernel no depende de WM_TIMER ni del bucle de mensajes, asi que
// hace falta esperarlo o sondearlo expresamente.
//
// Requiere Windows XP o superior; al compilar, el SDK debe definir
// _WIN32_WINNT >= 0x0400 (doc. Microsoft). La API vive en kernel32:
// no necesita librerias extra al enlazar.
//
// v2: la ventana pasaba de 350 a 385 de alto: el boton Cerrar
// (y=310) quedaba recortado por el borde inferior del area cliente.
// Y el literal "señalizado" del SAY se mostraba con mojibake en el
// Wine de validacion: los literales en pantalla van sin acentos ni
// eñes, como en ejemplos anteriores. Sin cambios funcionales.
//
// Documentacion de Microsoft:
//   https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw
//   https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-setwaitabletimer
//   https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-cancelwaitabletimer
//----------------------------------------------------------------------------//

#include "FiveWin.ch"

static oSayEstado, oSayDisparos, oSayUltimo
static nDisparos := 0
static cModo     := ""          // "", "UNICO" o "PERIODICO"

//----------------------------------------------------------------------------//

function Main()

   local oWnd
   local oTmr

   DEFINE WINDOW oWnd ;
      FROM 0, 0 TO 385, 500 PIXEL ;
      TITLE "CreateWaitableTimer: temporizador esperable"

   @ 15, 15 SAY "CreateWaitableTimer crea un temporizador como objeto del kernel:" OF oWnd SIZE 470, 15 PIXEL

   @ 33, 15 SAY "se activa con SetWaitableTimer, se espera con WaitForSingleObject" OF oWnd SIZE 470, 15 PIXEL

   @ 51, 15 SAY "y se cancela con CancelWaitableTimer (doc. Microsoft)." OF oWnd SIZE 470, 15 PIXEL

   @ 85, 15 BUTTON "Unico en 3 s" OF oWnd ;
      SIZE 145, 26 PIXEL ACTION BtnUnico()

   @ 85, 175 BUTTON "Periodico 1 s" OF oWnd ;
      SIZE 145, 26 PIXEL ACTION BtnPeriodico()

   @ 85, 335 BUTTON "Cancelar" OF oWnd ;
      SIZE 145, 26 PIXEL ACTION BtnCancelar()

   @ 130, 15 SAY "Estado:" OF oWnd SIZE 160, 18 PIXEL
   @ 130, 180 SAY oSayEstado PROMPT "" OF oWnd SIZE 305, 18 PIXEL

   @ 154, 15 SAY "Disparos recibidos:" OF oWnd SIZE 160, 18 PIXEL
   @ 154, 180 SAY oSayDisparos PROMPT "" OF oWnd SIZE 305, 18 PIXEL

   @ 178, 15 SAY "Hora del ultimo disparo:" OF oWnd SIZE 160, 18 PIXEL
   @ 178, 180 SAY oSayUltimo PROMPT "" OF oWnd SIZE 305, 18 PIXEL

   @ 215, 15 SAY "El sondeo lo hace un TIMER de FiveWin cada 100 ms: cuando el kernel" OF oWnd SIZE 470, 15 PIXEL

   @ 233, 15 SAY "marca el temporizador como senalizado, el programa lo anota aqui." OF oWnd SIZE 470, 15 PIXEL

   @ 258, 15 SAY "El temporizador del kernel no depende de WM_TIMER ni del bucle" OF oWnd SIZE 470, 15 PIXEL

   @ 276, 15 SAY "de mensajes (doc. Microsoft)." OF oWnd SIZE 470, 15 PIXEL

   @ 310, 200 BUTTON "Cerrar" OF oWnd ;
      SIZE 100, 26 PIXEL ACTION ( WT_Destroy(), oWnd:End() )

   DEFINE TIMER oTmr INTERVAL 100 ACTION PollTimer() OF oWnd

   ACTIVATE TIMER oTmr

   ACTIVATE WINDOW oWnd CENTERED

return nil

//----------------------------------------------------------------------------//

static function BtnUnico()

   if WT_Start( 3000, 0 )          // due relativo 3 s, sin periodo: unico
      nDisparos := 0
      cModo     := "UNICO"
      oSayEstado:SetText( "Esperando disparo unico (3 s)..." )
      oSayDisparos:SetText( "0" )
      oSayUltimo:SetText( "" )
   else
      oSayEstado:SetText( "(error " + ;
                          AllTrim( Str( WT_LastError() ) ) + ")" )
   endif

return nil

//----------------------------------------------------------------------------//

static function BtnPeriodico()

   if WT_Start( 1000, 1000 )       // due relativo 1 s, periodo 1 s
      nDisparos := 0
      cModo     := "PERIODICO"
      oSayEstado:SetText( "Periodico activo: cada 1 s" )
      oSayDisparos:SetText( "0" )
      oSayUltimo:SetText( "" )
   else
      oSayEstado:SetText( "(error " + ;
                          AllTrim( Str( WT_LastError() ) ) + ")" )
   endif

return nil

//----------------------------------------------------------------------------//

static function BtnCancelar()

   if cModo == ""
      oSayEstado:SetText( "No hay temporizador activo" )
   elseif WT_Cancel()
      oSayEstado:SetText( "Cancelado tras " + ;
                          AllTrim( Str( nDisparos ) ) + " disparo(s)" )
      cModo := ""
   else
      oSayEstado:SetText( "(error " + ;
                          AllTrim( Str( WT_LastError() ) ) + ")" )
   endif

return nil

//----------------------------------------------------------------------------//

static function PollTimer()

   local nRes := WT_Poll()

   do case
      case nRes == 1               // señalizado: la espera consume la señal
         nDisparos++
         oSayDisparos:SetText( AllTrim( Str( nDisparos ) ) )
         oSayUltimo:SetText( Time() )
         if cModo == "UNICO"
            oSayEstado:SetText( "Disparo unico recibido" )
            cModo := ""
         elseif cModo == "PERIODICO"
            oSayEstado:SetText( "Periodico activo: " + ;
                                AllTrim( Str( nDisparos ) ) + ;
                                " disparo(s)" )
         endif
      case nRes == -2              // error en la espera
         oSayEstado:SetText( "(error " + ;
                             AllTrim( Str( WT_LastError() ) ) + ")" )
   endcase

return nil

//----------------------------------------------------------------------------//

#pragma BEGINDUMP

#include <windows.h>
#include "hbapi.h"

// Handle del temporizador y ultimo GetLastError() de las WT_*
static HANDLE s_hTimer      = NULL;
static DWORD  s_dwLastError = 0;

// WT_Start( nDueMs, nPeriodMs ) -> lOk
// Crea el temporizador (auto-reset) si no existe y lo activa con un
// due time relativo: la doc. pide intervalos de 100 ns y valores
// negativos para tiempos relativos, asi que nDueMs se multiplica por
// 10000 y se cambia de signo. Si ya estaba activo, SetWaitableTimer
// lo detiene y lo reactiva (doc. Microsoft).
HB_FUNC( WT_START )
{
   LARGE_INTEGER liDue;
   LONG lPeriod = ( LONG ) hb_parnl( 2 );

   if( s_hTimer == NULL )
   {
      s_hTimer = CreateWaitableTimerA( NULL, FALSE, NULL );
      if( s_hTimer == NULL )
      {
         s_dwLastError = GetLastError();
         hb_retl( 0 );
         return;
      }
   }

   liDue.QuadPart = -( ( LONGLONG ) hb_parnl( 1 ) * 10000 );

   if( SetWaitableTimer( s_hTimer, &liDue, lPeriod, NULL, NULL, FALSE ) )
   {
      s_dwLastError = 0;
      hb_retl( 1 );
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_retl( 0 );
   }
}

// WT_Poll() -> 1 señalizado, 0 esperando, -1 sin temporizador, -2 error
// Espera con timeout 0: no bloquea el bucle de mensajes. Al ser
// auto-reset, la espera que devuelve WAIT_OBJECT_0 consume la señal.
HB_FUNC( WT_POLL )
{
   DWORD dwRes;

   if( s_hTimer == NULL )
   {
      hb_retni( -1 );
      return;
   }

   dwRes = WaitForSingleObject( s_hTimer, 0 );

   if( dwRes == WAIT_OBJECT_0 )
   {
      hb_retni( 1 );
   }
   else if( dwRes == WAIT_TIMEOUT )
   {
      hb_retni( 0 );
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_retni( -2 );
   }
}

// WT_Cancel() -> lOk. CancelWaitableTimer deja el temporizador
// inactivo; no cambia su estado de señalizacion (doc. Microsoft).
HB_FUNC( WT_CANCEL )
{
   if( s_hTimer == NULL )
   {
      hb_retl( 0 );
      return;
   }

   if( CancelWaitableTimer( s_hTimer ) )
   {
      s_dwLastError = 0;
      hb_retl( 1 );
   }
   else
   {
      s_dwLastError = GetLastError();
      hb_retl( 0 );
   }
}

// WT_Destroy(): cierra el handle. Tambien lo cerraria el sistema al
// terminar el proceso (doc. Microsoft), pero cerrarlo es lo correcto.
HB_FUNC( WT_DESTROY )
{
   if( s_hTimer != NULL )
   {
      CloseHandle( s_hTimer );
      s_hTimer = NULL;
   }
}

// WT_LastError() -> ultimo GetLastError() de las WT_*
HB_FUNC( WT_LASTERROR )
{
   hb_retnl( ( long ) s_dwLastError );
}

#pragma ENDDUMP

//----------------------------------------------------------------------------//

Cómo probarlo

  1. Compilar con FWH + Harbour y un MinGW con _WIN32_WINNT >= 0x0400; enlaza solo con kernel32, sin librerías extra. No está probado con otros compiladores ni SDK antiguos.
  2. "Unico en 3 s": el estado cambia a "esperando" y a los 3 segundos llega un solo disparo.
  3. "Periodico 1 s": el contador sube aproximadamente uno por segundo; "Cancelar" lo congela.
  4. "Cancelar" sin temporizador activo muestra el aviso correspondiente.

Validación del ejemplo (medida, no supuesta)

Compilado sin avisos con Harbour (win64), MinGW y FWH 26.10, ejecutado en Wine 11.19 el 10 de noviembre de 2026. Las cuatro capturas adjuntas corresponden a esta nueva corrida del código v2 mostrado arriba:

  • Estado inicial: controles y botón Cerrar visibles completos.
  • Disparo único: se recibió una señal aproximadamente 3 s después del clic; el contador mostró 1.
  • Periódico: se observaron 3 señales en aproximadamente 3 s, con periodo configurado de 1 s.
  • Cancelar con el periódico activo: el contador quedó en 3 y siguió en 3 al comprobarlo unos 2,3 s después.
  • El cierre con el botón Cerrar terminó el proceso limpiamente.

En esta corrida no se repitieron el rearme, la espera prolongada del disparo único ni Cancelar sin temporizador activo; no se presentan aquí como pruebas realizadas.
Ojo con los matices: los tiempos son aproximados, tomados de la corrida; el sondeo de 100 ms no acredita contar cada expiración bajo carga ni precisión temporal, y no lo afirmamos. Todo lo anterior es lo observado en ese Wine, no una afirmación sobre Windows nativo, donde el comportamiento puede ser distinto y no lo hemos probado. La resolución real del temporizador depende del hardware y del sistema (doc. Microsoft).
